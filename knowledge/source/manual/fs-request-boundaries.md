# 요청 경계의 근거 기반 검토

출처: FS 재설계에 관한 사용자와의 합의. 외부 표준의 인용이 아니라 조건부 설계 지침이다.

여러 화면이 같은 인증·응답 오류 정책을 반복한다면 기존 공용 클라이언트를 먼저 조사하고, 공유할 정책과 화면이 소유할 안내를 분리하는 대안을 검토한다.

컴포넌트 안의 fetch 또는 Axios 호출은 조사 계기이지 결함 판정이 아니다. 이미 사용하는 조회 계층, 호출자, 인증 경계와 오류 소비자를 확인한다. 하나의 단순 요청이나 서로 다른 정책을 억지로 공통화하지 않는다.

인증은 공통이어도 업무 오류 안내와 재시도 정책은 화면마다 다를 수 있다. 주문처럼 부작용이 있는 요청의 자동 재시도는 서버의 중복 방지 계약을 확인하기 전 확정하지 않는다. 네트워크 실패와 업무 거절을 구분할 필요도 사용자 계약으로 결정한다.

객체 입력과 요청 옵션의 소유권을 확인한다. 호출자 입력을 보존하기로 했다면 클라이언트가 전달받은 객체나 헤더를 수정하지 않는지 검사한다. 모든 객체를 깊은 복사해야 한다는 규칙은 아니다.

코드로 확인할 사항은 먼저 조사한다. 프로젝트의 인증 방식, 서로 다른 업무 정책, 재시도 허용처럼 조사만으로 알 수 없는 중요한 의도만 사용자에게 묻는다. 대안에는 기존 구조 유지, 기존 라이브러리 기능 재사용, 필요한 경계만 추가하기를 포함하고 비용을 설명한다.

선택된 계약에는 의존 경로, 입력 보존, 실패·재시도 시나리오 등 검증 방법을 연결한다. 네트워크 경계를 분리했다고 실제 렌더링·접근성이나 설계 품질 전체가 검증된 것은 아니다.
