## 출처 내용 요약

기존 props·state로 계산할 값과 특정 사용자 이벤트 처리를 Effect로 우회하지 않는다. 외부 시스템과 동기화하는 Effect는 별개이며 메모이제이션은 계산 비용을 확인한 뒤 판단한다.

추가 검토한 뒷부분은 key에 따른 상태 초기화, 선택 ID로부터의 값 계산, 이벤트 안의 상태 갱신·부모 알림, 앱 초기화, 외부 저장소 구독과 데이터 요청을 다룬다. 요청 Effect의 cleanup은 오래된 응답이 최신 결과를 덮어쓰지 않도록 하며, 외부 저장소 구독에는 useSyncExternalStore를 소개한다. 네 가지 연습문제는 파생 값 계산·캐시 또는 상태 배치·key 초기화·제출 이벤트의 구분을 다시 보여준다.

## 검토 해석과 제외한 주장

Effect 일괄 삭제 규칙으로 만들지 않는다. 선택 ID를 보존하는 방식과 목록 변경 때 선택을 지우는 방식은 동작이 다르다. 렌더 중 상태 갱신 예제는 같은 컴포넌트·반복 방지 조건에 한정되며 모든 컴포넌트에 권하는 패턴이 아니다.

검토 해석: cleanup의 ignore 플래그를 요청 취소로 설명하지 않는다. fetch 예제의 HTTP 오류·로딩 처리는 완성된 구현이 아니며 별도로 필요하다. 앱 초기화용 모듈 변수는 서버의 사용자별 인증 상태를 공유하는 근거가 아니다. useSyncExternalStore의 서버 snapshot 예시는 제품별 초기 상태 계약을 대신하지 않는다. 이 조건들을 기존 concept 참조에 보강하고 예제 실행·실제 성능 보장은 제외한다.
