# FS 반복 개선 기록

사용자 요청: 실제 비교 결과가 나올 때까지 개선 → 검증 → 비교 → 원인 분석을 반복한다. 시작일 2026-10-04.

## 유지할 기준

- 기존 v5의 과제·정답·채점기·모델(gpt-6-sol)·호출별 600초·격리 조건을 고정한다.
- 14/14, 사용자 결정/금지 준수, FS 승인·근거·검증 기록을 유지한다. 점수나 격리를 완화해 성공을 만들지 않는다.
- 성공한 모델 실행의 전체 토큰·비캐시 입력·시간을 비교한다. 누락 사용량은 null이다.
- 저장 분석 재사용 등록/실행, 부분 수정 성공/실패, 전체 조회와 반복 검사도 함께 기록한다.
- 한 번 좋은 결과가 나오면 같은 조건에서 재현 여부를 확인한다. 제품 코드가 동일하면 품질 우위로 보고하지 않는다. 처음 분석과 후속 재사용의 가치는 구분한다.
- 현재 완주한 FS 비교 기준은 161324의 1,910,803토큰·663.873초이며 180529는 시간 초과여서 전체 토큰 비교 기준으로 쓰지 않는다. 일반 AI와의 같은 회차 비교도 계속 병기한다.

## 직접 실행에 필요한 권한

초기 에이전트 세션은 workspace-write / approval_policy=never여서 외부 실행 승인을 요청할 수 없었다. 사용자 권한 변경 후 on-request가 적용되었고, `python3 test/evals/fs-comparison/v5/run.py` 실행 허용이 저장되었다. 평가 모델과 채점기 자체의 격리는 변경하지 않았다.

공식 안내: https://learn.chatgpt.com/docs/sandboxing

평가 모델과 채점기의 격리는 계속 유지한다. host에서 생성된 모델 코드를 실행하는 우회나 자동 권한 변경은 하지 않는다. 이 메모는 권한을 부여하는 설정 파일이 아니다.

## 고정 버전 재현 결과와 규격 도움말

194505와 195607은 runtime과 평가 코드까지 같은 독립 실행이다. 모두 양쪽 최초 14/14였으나 FS는 각각 2,042,988 / 2,686,188토큰, 467.544 / 552.979초, MCP 오류 0 / 13건이었다. 평균 2,364,588토큰으로 과거 161324의 1,910,803보다 많다. 시간은 두 회차 모두 짧았지만 안정적인 오류 제거와 토큰 절감은 재현되지 않았다.

195607에서는 save_project_context, save_revision, save_semantic_review 등에 빈 객체를 보내 오류 메시지로 필드를 알아내는 패턴이 반복됐다. 인용 줄 번호 오류는 사라졌으므로 다른 입력 규격 탐색 문제로 분리했다. 입력 규격이 모델에 어떻게 노출됐는지는 로그만으로 확정하지 않는다.

후속 보완은 build 시 실제 번들 MCP의 listTools 응답을 bundle/tool-schemas.json으로 자동 추출하고, 필요한 도구 규격만 출력하는 bundle/tool-help.mjs를 배포하는 것이다. 두 파일은 수작업 규격 복사본이 아니다. 스킬은 입력이 불확실하거나 검증 오류가 난 뒤 이 도움말을 읽고 재시도하도록 안내한다. 도구·프로젝트를 호출/수정하는 기능은 없다. 패키지 검사에서 실제 MCP 규격과 완전 일치, 두 도구 선택 출력, 알 수 없는 이름 거부를 확인했다. 77개 테스트·타입·린트도 통과했다.

201059와 202328은 manifest 전체가 같은 두 회차다. 둘 다 양쪽 최초 14/14, FS의 MCP 오류는 1/0건이었다. 그러나 FS 총 토큰은 1,916,728 / 3,174,514로 절감이 재현되지 않았다. 두 회차 평균 FS 2,545,621토큰·558.037초, 일반 AI 328,855토큰·227.257초다. 과거 161324 대비 FS 평균 토큰은 33.2% 많고 시간은 15.9% 짧다. 작은 표본의 시간 차이를 일반화하거나 토큰 절감으로 바꾸지 않는다. 202328에서는 도움말을 사용하지 않았으므로 입력 오류 감소를 도움말만의 인과적 효과로 주장하지 않는다.

## 검증 비용 후속 보완

202328은 MCP 오류가 없는데도 FS 비용이 컸다. Chromium 격리 오류, 대체 SSR 테스트의 util 로드 실패와 긴 data-URL 스택, delivery 통과 후 테스트 보강/재검증이 발생했다. 실패 이벤트 원문은 1,048,570문자였지만 실제 모델 입력의 출력 제한은 별도이므로 전체가 전달됐다고 단정하지 않는다.

기존 검사 요약은 실패 로그 끝 2,000문자만 반환해 앞쪽 원인을 놓칠 수 있었다. 같은 2,000문자 상한으로 앞·뒤를 요약하고 원본 저장과 capability/offset 읽기를 유지하도록 수정했다. 실제 MCP 회귀에서 실패 상태 유지, 앞쪽 오류/끝 표식 보존, 전체 로그의 페이지 단위 복원을 확인했다. fs-work는 개발 테스트도 프로젝트 스크립트의 MCP 경로를 쓰고, 테스트 개발/리뷰를 끝낸 뒤 최종 delivery를 실행하도록 순서를 정리했다. 원래의 완료·시도·최신성 검증은 유지한다. 막힌 브라우저의 같은 재시도와 SSR를 브라우저 검증으로 보고하는 것도 금한다.

타입·린트·78개 테스트, 독립 패키지 검사를 통과했다. 이 보완의 모델 비용 효과는 새로운 회차로 검증하며 앞선 두 번의 절감 실패를 보존한다.

204033을 완료했다. 일반 AI 425,027토큰·205.710초, FS 2,666,706토큰·582.529초, 양쪽 최초 외부 14/14다. FS의 MCP 입력 오류는 0건, 재사용 등록 3개·발동 합계 6회, 새 답변 부분 수정 1/1 성공이었다. 개발 테스트 4회를 MCP 경로로 실행했고 delivery는 1회였다. 브라우저 실패 로그는 원문 8,867문자/요약 2,000문자로 기록됐고 대체 UI 테스트의 null.type 오류를 수정했다. 원본을 폐기하거나 실패를 통과로 바꾸지 않았다.

하지만 FS 총 토큰은 일반 AI의 6.27배이며 과거 161324보다 39.6% 많다. 도움말 12회와 MCP 25회 등 기록·규격·검증 문맥의 처리 비용이 남았다. 입력 오류 제거·제한된 출력·최종 검사 1회가 전체 토큰 절감으로 이어진다고 입증하지 못했다. **8쌍을 직접 완료한 이번 반복의 비용 목표는 미달이다.** 기능 연결과 보호 조건의 개선은 확인했지만 효율·구현 준수 우위로 바꾸어 보고하지 않는다. 가설과 개입 없이 유리한 회차가 나올 때까지 재실행하는 것은 검증으로 삼지 않는다.
