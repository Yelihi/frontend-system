# 흐름 분석·설계 연결 구현 계획

사용자가 2026-10-06 논의한 변경과 실제 시각화·평가를 승인했다. 기존 변경을 보존하며
코드 근거, 사용자 의도, 제안된 흐름, 실행 검증을 구분한다. 자동 커밋·배포는 범위 밖이다.

## 구현 계약

- 분석 순서: 환경/진입점 → 의존 경계 → 이벤트/상태/오류 흐름 → 지식 조사 → 개선 항목.
- 흐름은 지식 등록과 독립적으로 저장한다. 인용·의존 파일·구성 및 새 파일 발견 범위로
  최신성을 확인한다. 동적 호출/외부 경계는 미확인으로 남기고 완전한 실행 그래프를 주장하지 않는다.
- 페이지/중첩 컴포넌트, props/state/events/lifecycle, 외부 store/cache/module을 기록하고
  이벤트별 단계·분기·영향 블록을 같은 데이터에서 HTML과 Mermaid로 출력한다.
- 개선 항목은 근거·지식·대안·질문·권한을 갖고, 해결/제외/보류 기록을 삭제하지 않는다.
- 계획은 선택한 분석 기록의 정확한 버전과 연결하며, 새 요구와 변경 범위의 추가 조사를 허용한다.
  승인/작업 시작 전에 오래된 참조를 거부한다. 구현 중 정상 코드 변경을 과거 분석 위반으로 오인하지 않는다.
- project.md는 수동 갱신하는 main 색인이다. 상세 파일/manifest/근거를 반복 출력하지 않는다.
  작업 변경과 최신성은 별도로 조회한다. 제안된 새 기능을 구현 사실로 저장하지 않는다.
- 대표 기존 지식부터 원문이 뒷받침하는 조사 명세를 이전한다. 나머지는 이전 미완료로 표시하며
  조건을 발명해 공용 필수 규칙으로 승격하지 않는다.
- 새 기능은 목표/예외/상태 흐름/선택 → 기존 분석 및 지식 → 결정 → 기존 plan 계약으로 전달한다.

## 검증과 반복

1. 저장·인용·최신성·계획 참조·해결 이력·렌더 안전성의 결정적 회귀.
2. 중첩 블록과 이벤트 선택의 실제 브라우저 확인 및 스크린샷.
3. 고정 프로젝트의 초기 분석 → 변경된 호출부/계약 → 계획 작성. 일반/동일 지식/FS의
   독립 세션과 동일 입력을 사용하고, 적용 조건·제외 조건·미확인·이전 결정 재사용을 관찰한다.
4. 오류를 보존하고 원인을 수정한 경우에만 새 이름의 재실험을 실행한다. 총/비캐시 토큰,
   잘못된 연결·계약 누락·중복 질문·미검증 결과를 각각 기록한다. 점수나 정답을 결과에 맞춰 바꾸지 않는다.
5. 확인된 실패가 해소되고 후속 회귀가 유지되는지 확인한다. 비용/설계 우위가 없으면 그대로 보고한다.
