# 코드 근거 기반 지식 라우팅

2026-10-02 사용자 요청에 따른 구현 계획. 기존 미커밋 변경을 유지한다.

## 계약

호스트가 작업 코드를 읽고 필요한 파일을 선택한다. FS는 선택한 JS/TS 파일의
import·React 호출·경로 사실을 수집하고, 근거를 갖춘 호스트 해석을 합쳐 지식의
트리거와 체크리스트를 조회한다. 호출 발견은 수정 의무가 아니다.

1. 기존 TypeScript 파서를 재사용한다. 이름 별칭과 스코프 가림을 구분한다.
   tsconfig 경로 해석은 참고 사실로 반환하고, 재수출·동적 경로·미지원 문법은
   미해결로 남긴다. 전체 저장소/AST/타입 검사를 모델에 전달하지 않는다.
2. 지식 인덱스에 선택적인 triggers/checks를 추가한다. 기존 버전과 단어 검색을
   보존한다. 직접 트리거는 단어 검색의 상위 5개 제한과 분리한다.
3. 체크 응답은 코드·인덱스 해시에 연결한다. 누락·중복·낡은 결과를 거부하고
   적용/유지/해당 없음/추가 맥락/사용자 결정 필요를 기록한다. 검토 완료와
   동작 검증 완료를 구분하며 기존 정책·검사·의미 검토를 대체하지 않는다.
4. sync 시 트리거 메타데이터와 고정 검색 사례를 검증한다. 대표 React Effect,
   상태 수명, 의존 경계, 성능 조사 지식부터 연결한다.
5. Skill, MCP, 사용 문서를 연결하고 정상/오탐/별칭/낡은 근거/누락 사례와
   독립 패키지 실행을 검증한다. 로컬 측정은 모델 토큰 절감 증거와 구분한다.

## 범위

기본 탐색은 대상 프로젝트의 ESLint 설치를 요구하지 않는다. TypeScript를 FS의
런타임 의존성으로 명시한다. 대상 프로젝트의 lint·타입·아키텍처 정책은 기존
실행기를 사용한다. 자동 레이어 추정으로 금지 규칙을 만들거나 코드를 고치지 않는다.
분석 대상은 명시적 파일 목록이며 누락된 파일에 대한 완전성을 주장하지 않는다.

런타임 검증은 사용자 증상·동작 계약·호스트 해석에 의해 요청한다. Profiler는
실행 중인 React 트리에서만 측정한다. dev 서버에서 가능하지만 정적 분석/SSR
만으로 브라우저 렌더 성능을 증명하지 않는다. Fiber 수집, Jev/Laya API,
전체 의미 그래프, 모델 비교 실험, 커밋·배포는 이번 구현 범위에 포함하지 않는다.
