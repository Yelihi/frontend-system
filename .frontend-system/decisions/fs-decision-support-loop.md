# FS의 중심: 근거를 갖춘 선택 제안과 결과 기반 재평가

- 날짜: 2026-09-29
- 출처: 사용자의 FS 방향 설명
- 범위: 제품 방향 명확화. 전체 구현안 승인 또는 공용 규칙 배포가 아님.

## 사용자 의도

개발자가 중요한 선택을 한다. FS는 축적된 sources, 지식, skills/references의 상황 메타데이터, 현재 코드와 최상위 모델의 판단을 연결하여 놓치기 쉬운 고려 사항을 발견하고 선택지를 제안한다. 개발자가 먼저 제기한 대안도 함께 논의한다. 선택 후 review·test와 검증 도구로 결과를 확인하고 유지하거나 변경하며, 기록과 피드백으로 다음 판단을 개선한다.

## 방향

제안에는 상황, 유효한 대안, 트레이드오프, 추천 전제와 근거, 실패 조건, 검증 방법을 포함한다. 선택 당시 이유·기대와 실행 후 관찰을 분리한다. 필수 안전 조건을 충족하는 안들을 비교하며, 미검증 조건을 통과로 보고하지 않는다.

기존 fs-work 계약 준수 합의는 유지한다. 새로운 중요한 선택은 개발자와 논의하고, 이미 합의한 계약 안의 내부 구현은 재량으로 처리한다. 반복 승인이나 모든 지역 구현 선택의 질문을 요구하는 방향이 아니다.

선택의 수정은 구현 결함, 환경·요구 변화, 추천 전제 오류, 검증 부족을 구분해 기록한다. 상황 메타데이터와 반례를 유지하며 공용 지식 반영은 사용자 지시 후 진행한다.

- 실제 선택 제안의 품질·개선 수치: 아직 측정하지 않음.
- 후속 평가: 중요한 선택 누락, 부적절한 대안·추천, 불필요한 질문, 후속 증거에 따른 판단 수정.
- 재검토: 실제 사용에서 선택 부담이 늘거나, 중요한 선택을 놓치거나, 사용자 선택을 사후 정당화하는 문제가 관찰될 때.
- 검색 맥락: 판단 기준, 선택 제안, 트레이드오프, 개발자 결정, 사전 기대, 결과 검증, 피드백 순환.
