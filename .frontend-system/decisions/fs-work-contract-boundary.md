# fs-work의 계약 준수와 구현 재량

- 결정일: 2026-09-29
- 결정자: 사용자
- 범위: FS 방향 초안의 fs-work 역할과 재량
- 상태: 방향 합의. 전체 설계 승인·구현 완료·공용 규칙 배포를 뜻하지 않음.

## 질문과 답변

질문: 도메인·상태 소유권·의존 방향·핵심 인터페이스를 고정하고 내부 지역 변수·보조 함수에는 계약을 유지하는 재량을 허용할 것인가?

사용자 답변: “fs-work 는 말 그대로 실제 구현하는 단계입니다. 말씀하신대로 최대한 계약을 지킵니다. 그렇게 가면 되겠습니다.”

## 결정과 이유

fs-work은 승인된 설계와 이슈 계약에 충실하게 구현한다. 중요한 제품·설계 판단을 구현 단계에서 다시 만들지 않되, 계약을 바꾸지 않는 내부 구현은 매번 질문하지 않고 진행한다. 모든 지역 이름까지 일률적으로 고정하는 방식 대신 이 경계를 채택했다.

도메인 동작, 상태 소유권, 의존 방향, 지정된 공개 인터페이스, 수용 기준은 유지한다. 사용자가 지정한 파일·함수명도 계약으로 따른다. 내부 지역 변수와 국소 보조 함수는 계약을 유지하는 범위에서 선택할 수 있다.

계획의 모순이나 구현 불가능성이 드러나거나 제품 동작·경계·테스트 기대값을 바꿔야 하면, 관련 작업을 진행하기 전에 문제와 대안을 개발자에게 제시한다. 독립적인 승인 범위의 작업은 계속할 수 있다.

## 근거와 한계

- 연결 문서: docs/fs-direction-draft.md, 7절과 13절.
- 결과: 논의용 초안에 합의 반영. 스킬·런타임 코드는 이번 결정 기록에서 변경하지 않았다.
- 효과 측정: 미실행. 재작업 감소·정확성 향상을 수치로 주장하지 않는다.
- 재검토 조건: 실제 이슈에서 반복적인 계약 이탈 또는 사소한 질문으로 작업이 지연되거나, 프로젝트가 더 엄격한 이름·파일 규약을 요구할 때.
- 검색 맥락: fs-work, 구현 재량, 계약 준수, 계획 이탈, 내부 구현, 개발자 질문.
