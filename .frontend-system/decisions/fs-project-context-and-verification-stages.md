# project.md와 단계별 검증 역할 재정리

- 날짜: 2026-09-30
- 출처: 사용자의 프로젝트 문서·plan/work/review/knowledge 역할 재정의 제안.
- 상태: 제품 방향 초안 v0.5에 반영. 개별 구현 계약·정확한 경로·외부 설치·CI bot 권한은 미확정.

## 사용자 방향

프로젝트마다 main 기준의 공식 project.md 하나를 AI가 관리한다. 초기 분석과 main 변경 후 패키지·트리·테스트·lint 근거를 수집하고 도메인·함수 이벤트·레이어·패칭·스타일을 해석해 갱신한다. plan은 그 context와 sync 지식으로 논의해 요청별 설계와 최소 이슈를 만든다. work는 plan대로 구현하고 자동 필수 검사와 AI 리뷰·계약 테스트를 수행한다. review는 실제 화면과 성능·통신·메모리·번들 측정에서 개선을 제안한다. knowledge는 원본 FS를 갱신하며 소비 프로젝트에서도 원본으로 기여 PR을 만들 수 있어야 한다. Archify·dependency-cruiser 설치와 브라우저 도구 연결은 사전 동의를 받는다.

## 구체화한 제안

- 단계별 script 시점은 docs/fs-direction-draft.md 2.1 표에 정리했다. 계획 구조 검증과 아직 없는 제품 코드의 검증을 구분한다.
- 초기 공개 명령은 네 개를 유지하고 project.md 초기 작성은 fs-plan 흐름에 포함하는 안을 제안했다. 별도 fs-init 명령은 아직 확정하지 않았다.
- main 분석 커밋·갱신 상태를 표시하고 비동기 갱신 지연/실패를 최신으로 숨기지 않는다. 생성 중 main 변경과 문서 생성 루프를 처리해야 한다. 문서 갱신 PR은 추천이며 bot 직접 쓰기 권한은 별도다.
- review에서 채택한 변경도 plan/work와 동일 조건 재측정으로 연결한다. 검토만 요청의 쓰기 제한을 유지하고 이미 승인된 개선은 반복 확인하지 않는다.
- WebMCP와 Chrome DevTools MCP를 구분했다. 실제 Network·trace·heap 수집 후보는 후자이며 HAR·React 렌더·번들·운영 지표 지원은 별도 확인한다.
- 기존 init.md/legacy project.md 로딩, 단일 revision/execution, 읽기 전용 review, 고정 검사 순서는 현재 구현이다. 제안한 새 실행 계약은 아직 적용되지 않았다.

## 결과와 재검토

변경한 것은 방향 초안과 이 기록뿐이다. 실행기·공개 스킬·CI 자동화·도구 설치·제품 코드·PR을 변경/실행하지 않았다. 로컬 문서 링크·코드 fence·git diff 공백 검사를 통과했다. 토큰 절감이나 품질 향상은 미측정이다.

대표 프로젝트의 실제 script에 매핑할 때 과도한 반복 실행, 검사 누락, 문서 stale 오인, 측정 환경 불일치가 생기면 해당 단계를 수정한다. 이전 요청별 계획 방향은 유지하며 project.md가 공식 현재 상태를 담당하도록 확장한다.
