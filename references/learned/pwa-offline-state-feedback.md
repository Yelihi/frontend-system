# 오프라인 작업·저장·동기화 상태의 사용자 피드백

검토일: 2026-09-21 · concept · experience

## 참고 상황

네트워크가 끊겨도 읽기·편집을 이어가야 하거나 로컬 저장을 서버 동기화 완료로 오해하는 UI를 설계할 때.

## 판단에 사용할 내용

가능한 작업, 콘텐츠 신선도, 로컬 저장·동기화 대기·서버 완료 상태를 구분해 표시와 재시도 흐름을 정한다.

## 적용하지 않는 경우

온라인 처리가 필요한 결제·권한 변경의 성공을 연결 신호만으로 표시하거나 모든 데이터를 자동 캐시하지 않는다.

## 개념과 근거

사용자가 무엇을 계속할 수 있는지와 데이터가 어디까지 저장되었는지를 알리는 것이 목적이다. 새 콘텐츠 자동 반영이 읽던 위치를 방해할 수 있고, 큰 다운로드는 용량·비용과 사용자 선택을 고려한다.

색상·아이콘만으로 상태를 전하지 않고 작업 중심의 문구를 함께 사용한다. 특정 toast나 자동 다운로드는 원문의 사례다. UI 문구만으로 재시도·충돌 해결·서버 반영이 구현되지는 않으므로 실제 처리 상태와 표현을 맞춘다.

## 검토한 출처와 범위

- [web.dev — Offline UX design guidelines](https://web.dev/articles/offline-ux-design-guidelines) — 연결 변화·콘텐츠 신선도·다운로드·저장 및 동기화 상태·언어와 피드백 지침. 링크된 서비스워커 구현은 제외.

적용 조건: 오프라인·불안정 연결 지원이 요구되는 웹 앱. 실제 저장·전송 기능이 있는 범위에 한정한다.

읽은 범위의 개념 참조이며 제품 코드·예제 실행, 접근성·보안·성능 검증 완료를 뜻하지 않는다.
