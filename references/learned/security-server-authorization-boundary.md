# OWASP 2025 위험 탐색과 서버 인가의 경계

검토일: 2026-09-21 · concept · public-contract

## 참고 상황

관리자 버튼·라우트 가드를 숨기는 것으로 권한을 막았는지, 다른 사용자의 객체 ID 요청이 허용되는지 검토할 때.

## 판단에 사용할 내용

UI 표시와 서버 인가를 구분하고 사용자·행위·대상 레코드별 권한 검증이 신뢰 경계 안에서 수행되는지 확인한다.

## 적용하지 않는 경우

Top 10 목록을 완전한 보안 인증·검증 목록으로 취급하거나 프런트엔드 분기만으로 권한을 보장하지 않는다.

## 개념과 근거

Top 10은 위험 인식을 위한 분류이며 이번 상세 범위는 A01이다. URL·객체 ID·요청을 변경할 수 있는 클라이언트의 검사는 서버의 접근 제어를 대신할 수 없다. 로그인 여부와 특정 레코드·행위에 대한 권한도 구분한다.

검토 질문은 권한 없는 사용자·다른 소유자의 객체·다른 행위로 요청했을 때 신뢰 가능한 서버가 거절하는가이다. 이는 후속 검증 방향이며 이번에 API 보안 테스트를 수행한 결과가 아니다. A02–A10의 구체적 방어 처방과 표본 발생률의 일반화는 제외한다.

## 검토한 출처와 범위

- [OWASP Top 10:2025 — Overview](https://top10.owasp.org/2025/) — 2025판 소개와 위험 10개 분류 목록. 상세 검토는 별도 등록한 A01에 한정.
- [OWASP Top 10:2025 — A01 Broken Access Control](https://top10.owasp.org/2025/A01_2025-Broken_Access_Control/) — 설명·예방·접근 권한 우회 사례. 전체 CWE와 외부 자료는 제외.

적용 조건: OWASP Top 10:2025 개요와 A01 접근 제어. 실제 서버/API와 보호 자산을 함께 검토한다.

읽은 범위의 개념 참조이며 제품 코드·예제 실행, 접근성·보안·성능 검증 완료를 뜻하지 않는다.
