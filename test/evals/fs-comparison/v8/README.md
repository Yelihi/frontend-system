# v8: 문서 발견과 후속 변경

사전 등록(모델 실행 전): v7의 정답률 상한을 숨기지 않고, 상세 구현 계획을 제공하지 않은 프로젝트에서 팀 지식 발견과 유지보수를 비교한다.

- `ordinary`: 일반 작업 지시. 팀 지식/문서 접근 가능, 관련 문서의 개별 위치 안내 없음(지식 루트는 공통 안내).
- `informed`: 같은 지시 + TEAM_POLICY.md와 관련 지식 위치 안내. FS 없이 계획/구현.
- `fs`: informed와 같은 정보 + FS 라우팅/근거/승인/검증 절차.

ordinary↔informed는 지식 위치 안내 효과이며 지식 자체의 우열이 아니다. informed↔fs는 절차 추가 효과다. 모든 조건에 같은 소스/의존성/문서/공개 검사기를 제공한다. 숨겨진 개인 취향으로 불합격시키지 않는다. ordinary도 CONTRACT.md에서 팀 규칙 적용 사실을 읽을 수 있다.

같은 프로젝트를 `initial` → `variants` → `defaults` 순으로 유지한다. 단계마다 새로운 대화와 MCP 프로세스, 코드/이전 계획/팀 문서는 유지한다. prepare와 work만 동일 단계의 대화를 재개한다. 각 조건은 독립 checkout으로 시작한다. 단계 사이 평가기가 결과를 main에 커밋한다(외부 push 없음). FS의 main 분석도 그 결과로 갱신해야 한다. 이전 단계가 실패하면 해당 조건의 후속 단계는 실행하지 않는다. 이전 조건의 코드를 다른 조건으로 복사하지 않는다.

1. initial: 기존 v7의 화면 동등 스타일 결함을 수정. 테마 전략을 질문한 뒤 선택대로 적용.
2. variants: 세 컴포넌트에 새 변형을 추가하면서 기존 모든 조합/기능 유지. 새 기본값 정책은 질문.
3. defaults: 기존 선택을 명시적으로 변경. 새 변형을 삭제하거나 이전 default를 고수하지 않고 최신 결정 반영.

평가: 독립 v6/v7 기능/구조 검사 93개 + 별도 변형/기본값/컴파일 범위 검사. 초기 비용/단계별 비용/누적 비용, 첫 시도/복구 후 점수, 질문 프로토콜과 FS 절차 완료를 각각 기록한다. 같은 93개 점수여도 변형 조합 수가 늘어나므로 비교 수를 함께 기록한다. 질문은 고정 주제/응답 프로토콜이며 질문의 의미적 품질·자율적 발견을 입증하지 않는다. 모델의 실제 출력에만 점수를 매기며 정답 구현을 전달하지 않는다.

우위 판정은 첫 시도 규칙/기능/최신 결정 준수와 전체 비용을 함께 본다. 동점은 우위가 아니다. 추가 비용을 정당화하는 오류 감소가 없으면 그대로 실패/한계로 기록한다. 단일 표본에는 통계적 우위를 주장하지 않는다. 최소 두 실행 순서(ordinary→informed→fs, fs→informed→ordinary)를 사용하며, 수정하면 manifest를 분리한다. 외부 복구는 단계당 최대 1회. 인프라 중단/미보고 토큰은 실패/0토큰으로 바꾸지 않는다. 모델이 만든 코드는 기존 제한된 실행기로만 평가한다.

```sh
python3 test/evals/fs-comparison/v8/run.py --calibrate-only
python3 test/evals/fs-comparison/v8/run.py --run --model gpt-6-sol
python3 test/evals/fs-comparison/v8/run.py --run --model gpt-6-sol --reverse
```

범위: 4개 도메인 37개 제품 파일(계약 추적 35개 JS/JSX와 CSS, 보호 helper money.mjs)을 유지하며 변경 이력/조합/결정 변경을 확장한다. 실제 브라우저, 임의 코드의 완전한 의미 검증, 모든 디자인 패턴의 우월성을 입증하지 않는다. 기존 v7 결과는 수정하지 않는다.

## 동일 코드 진단 재현 — 모델 호출 전 등록

D의 성공한 FS variants snapshot을 **양쪽에 동일하게** 제공하여 defaults 요청만 informed/FS로 실행한다. 공개 문서와 제품·테스트 코드는 같고, 과거 `.frontend-system` 승인/실행 기록은 양쪽 모두 제거하며 새 대화·계획을 만든다. 먼저 제한된 검사기로 출발 코드가 variants 계약을 통과하는지 확인한다. 모델 생성 코드는 호스트에서 실행하지 않는다. 비교 대상마다 코드·상태를 새로 복원하고 동일한 defaults 계약/외부 복구 한도1회를 적용한다.
