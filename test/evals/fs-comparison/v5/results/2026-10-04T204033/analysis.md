# 검증 로그·검사 순서 보완 후 실제 비교

gpt-6-sol, 각 호출 600초, 동일 v5 계약·채점·격리다. 직전 202328과 manifest의 runtime/hash만 다르고 나머지 조건은 같다. 양쪽 최초 외부 검사 14/14, 금지·사용자 결정 위반 0건, 외부 수정 호출 0회다. 내부 개발 테스트의 실패·수정이 없었다는 뜻은 아니다.

| 지표 | 일반 AI | FS |
| --- | ---: | ---: |
| 전체 토큰 | 425,027 | 2,666,706 |
| 비캐시 입력 | 45,296 | 111,617 |
| 모델 실행 시간(초) | 205.710 | 582.529 |
| 준비 토큰 | 85,490 | 529,313 |
| 구현 토큰 | 339,537 | 2,137,393 |
| MCP 호출 / 입력 오류 | 0 / 0 | 25 / 0 |

FS/일반 비율은 전체 토큰 6.27배, 비캐시 입력 2.46배, 시간 2.83배다. 과거 161324 대비 FS 토큰은 39.6% 많고 시간은 12.3% 짧다. 직전 큰 실패 회차의 3,174,514토큰보다 적다는 것만으로 안정적 절감을 주장하지 않는다. 새 버전의 단일 실행이며 일반 우위나 인과적 절감량은 입증하지 않는다.

## 실제 사용과 남은 비용

- 분석 진술 4개 중 재사용 3개, 명시적 제외 1개. 두 맥락 조회에서 발동 합계 6회다. 같은 사실의 재발동을 독립 지식 수나 절감량으로 세지 않는다.
- 새 답변의 근거를 함께 연결한 결정 부분 수정 1/1 성공, 전체 revision 조회 0회, 소스 묶음 조회 1회다.
- 검사 도구는 baseline 1회, 개발 테스트 4회, delivery 1회였다. 개발 테스트는 통과 → 브라우저 환경 실패 → 대체 UI 테스트의 null.type 오류 → 통과였다. 오류 수정 후 최종 delivery와 필수 리뷰를 마치고 execution=complete/verified를 확인했다.
- 브라우저 실패의 8,867문자 원문은 기록에 남고 응답에는 2,000문자 요약이 전달됐다. 대체 테스트 실패 1,608문자는 그대로 전달됐다. get_check_record로 전체 로그를 다시 읽는 호출은 없었다. 실제 브라우저 성공은 여전히 미검증이며 모의 이벤트/렌더 검증으로 대신 증명했다고 주장하지 않는다.
- 도움말은 12번, 출력 합계 31,182문자였다. 개별 규격을 확인하는 비용도 남는다. 셸 명령 완료 이벤트는 일반 AI 20개, FS 30개였고 FS에는 MCP 25개가 더 있었다. 이 수를 추론 호출 수나 코드 결함 수로 해석하지 않는다.

FS 추가 2,241,679토큰 중 캐시 입력 증가분이 2,162,176(96.45%)이다. 비캐시 입력도 증가했다. 전체 호스트 문맥은 공개되지 않으므로 도움말/기록/특정 테스트에 토큰을 정확히 배분하지 않는다. 총 토큰 배수는 청구 금액 배수가 아니다.

일반 AI는 테스트를 먼저 추가해 기존 코드의 계약 위반을 확인하고 수정했다. 그 의도된 실패를 새 구현 오류로 세지 않는다. 제품 6개 파일은 바이트 단위로 같고 domain/orders.mjs는 일반 AI의 할인 조건에 kind === 'purchase'가 추가된 차이만 있다. FS는 앞선 검증에서 gift 쿠폰을 거부하므로 기존 계산식을 유지했다. 이 관찰과 14개 유한 검사로 모든 입력/설계 품질의 동등성을 증명하지 않는다.

## 결론

분석 재사용, 새 답변 부분 수정, 근거·승인·완료 검증과 로그 요약의 실제 실행은 확인했다. 최신 보완에서도 총 토큰과 계획 준수의 우위는 확인하지 못했다. 입력 오류와 거대한 로그를 줄이는 것만으로 전체 기록·규격 조회·검증 문맥의 반복 처리 비용이 없어지지는 않았다. 이번 반복 개선의 비용 목표는 미달이며, 좋은 회차만 선택하거나 계약·채점을 낮춰 성공으로 바꾸지 않는다.
