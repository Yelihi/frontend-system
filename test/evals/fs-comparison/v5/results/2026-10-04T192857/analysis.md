# 3차 반복 개선 실측

양쪽 모두 최초 외부 채점 14/14, 금지·결정 위반 0건, 외부 수정 호출 0회였다. FS는 근거·승인·시도·검사·검토·완료 경로를 마쳤다. **시간은 더 줄었지만 총 토큰은 직전보다 늘었다. 재사용 등록 자체가 토큰 절감을 보장하지 않는다.**

| 비캐시 입력 | 34,741 | 74,732 |

FS/일반은 전체 토큰 3.31배, 시간 1.13배지만, 일반 AI가 브라우저 권한 오류를 복구하느라 비용이 증가한 영향이 있다. 이를 FS 성능 우위로 해석하지 않는다. FS 절대 토큰은 191629 대비 약 20.8% 증가, 시간은 약 11.8% 감소했다. 161324 FS 대비 시간은 약 35.2% 감소했지만 토큰은 약 21.7% 증가했다.

등록 신호를 먼저 확인한 뒤 저장 진술 4개 중 1개를 재사용하도록 연결했다. 관측 발동은 1회였다. 묶음 소스 읽기 1회, 지식 읽기 2회, 새 답변 부분 수정 1/1 성공, 전체 revision 조회 0회였다.

MCP 실패는 (1) 코드 인용의 잘못된 줄 번호, (2) issue.acceptance에 배열 대신 문자열, (3) planId 없이 만든 기준 검사 ID를 named plan에 연결한 경우였다. 각각 거부 후 복구했다. 같은 인용 오류가 두 실행에 나타났으므로 다음 버전에서 고유한 정확 인용문의 줄 번호를 서버가 계산하도록 보완한다. 명시한 잘못된 줄, 중복 인용, 변경된 해시를 허용하는 수정은 하지 않는다.

공통 결정 필드의 intersection 선언은 MCP 변환 후 같은 입력 규격 크기였으므로 최적화로 집계하지 않았다. 다음 버전은 상태별 선택 조건을 서버에서 동일하게 검증하면서 공통 필드를 한 번만 노출한다.

모델·호출별 600초·과제·채점기·격리·plain→FS 순서는 동일하다. 초기 분석부터 시작하는 단일 과제이며 장기 유지보수의 누적 효과를 측정한 것은 아니다. 원자료와 telemetry.json/md를 보존한다.
