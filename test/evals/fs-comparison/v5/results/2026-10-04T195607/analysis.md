## 재현에서 확인된 문제

준비 8건, 구현 5건의 MCP 오류가 발생했다. 필수 expectedCommit 누락, mode:plan 사용, 빈 save_project_context와 save_revision 호출, 불완전한 issue/decision 구조, get_check_record의 id 누락, execution 구조 오류, 빈 semantic review/findings 탐색, 완료 시 attemptId 누락이었다. 사용자 선택이나 검증 조건을 느슨하게 만들어 통과시키지는 않았다.

특히 save_project_context, save_revision, save_semantic_review에 빈 객체/불완전 객체를 보내고 오류 메시지로 필드를 알아내는 호출 패턴이 반복됐다. 코드 인용 위치 자동화로 해결한 오류와 다른 문제다. 모든 도구 규격이 실제 모델 입력에 어떻게 노출됐는지는 이 로그로 증명하지 못하므로 SDK가 규격을 숨겼다고 단정하지 않는다.

동일 버전 첫 회차 대비 FS 토큰은 약 31.5%, 시간은 약 18.3% 증가했다. 두 회차 평균 FS는 2,364,588토큰·510.262초이며 일반 AI는 307,504.5토큰·180.382초다. 일반 대비 평균 총 토큰 약 7.69배다. 이 두 번의 결과로 안정적 오류 감소나 총 토큰 절감을 주장할 수 없다. 첫 회차만 선택해 보고하지 않는다.

## 후속 보완

실제 번들 MCP의 listTools에서 입력 규격을 자동 추출해 bundle/tool-schemas.json과 읽기 전용 tool-help.mjs를 배포한다. 불확실한 입력이나 검증 오류 후에는 필요한 도구의 규격을 읽고 재시도하도록 안내한다. 잘못된 저장 호출로 입력 형식을 탐색하는 비용을 줄이기 위한 조치이며, 이 문서 시점에서는 다음 실제 비교로 검증해야 한다. 사용자 결정·승인·근거·시도·완료 검증은 그대로다.

원자료와 telemetry.json/md는 보존한다. 브라우저 권한 제한에 따른 검증 범위도 실제 브라우저 성공으로 바꾸지 않는다.
