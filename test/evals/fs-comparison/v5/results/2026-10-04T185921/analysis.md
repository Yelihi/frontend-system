두 arm 모두 최초 구현에서 14/14, 금지·사용자 결정 위반 0건, 외부 수정 호출 0회였다. FS도 모델 응답과 외부 채점까지 완료했다. 최종 제품 파일 7개는 바이트 단위로 같다. **절차 결함은 줄었지만 비용 개선과 구현 품질 우위는 입증되지 않았다.**

FS/일반 AI는 총 토큰 약 8.63배, 비캐시 입력 2.20배, 시간 2.94배다. 캐시 입력은 input_tokens의 부분집합이며 전체 토큰에 다시 더하지 않았다. 총 토큰 비율은 비용 청구 비율이 아니다.

## 확인된 개선

- 7개 분석 진술 중 4개에 의존성과 등록 신호를 연결했고, 나머지 3개는 reuseReason을 명시했다. 두 context 조회에서 각각 4개의 저장 신호가 재사용되어 관측 합계는 8이다. 독립된 사실 8개 또는 절감 토큰을 뜻하지 않는다.
- 새 USER_DECISIONS.md를 포함한 evidenceRoutes와 decisionUpdates를 함께 저장해 1회에 성공했다.
- 전체 revision 조회 0회. decisions/contract 조회 각 1회.
- 단일 이슈로 실행해 계층별 검사·시도 중복을 줄였다. 시간 초과 없이 완료했다.

## 남은 비용과 오류

- 소스 본문 총 약 5,825 응답 문자를 얻기 위해 read_project_source를 11회 호출했다. 선택한 지식 4개도 4회 호출했다. 호출마다 누적 문맥을 처리하므로 작은 개별 응답만 줄여서는 전체 토큰이 줄지 않는다.
- 준비 과정의 run_project_checks는 stage와 capabilities를 함께 보내 실패했다. stage:baseline으로 복구한 뒤 build를 별도로 실행했다. baseline stage가 build를 제외한다는 동작과 실제 인수명(capabilities)을 더 명확히 안내해야 한다.
- 구현에서는 save_execution 전에 revision 해시로 begin_work_attempt를 호출해 실패했다. 실행 초기화 후 execution 해시로 복구했다. 도구 설명에서 두 해시를 구분할 필요가 있다.
- get_work_context 2회 응답 약 45,795문자, get_revision 2회 약 16,932문자, save_revision 입력 2회 약 16,468문자였다. 문자는 토큰과 같지 않으며, 이 수치만으로 각 항목의 인과적 토큰 기여도를 계산하지 않는다.
- 브라우저는 권한 오류로 실행되지 않았다. FS가 수행한 Node/컴포넌트 검증과 외부 14개 검사를 실제 브라우저 성공으로 대체해 해석하지 않는다. shell 오류에는 브라우저 실패와 macOS nl의 다중 파일 인수 오류도 있었다.

## 통제와 한계

gpt-6-sol, 호출별 600초, 같은 계약·fixture·채점기·격리 설정을 유지했다. main/preparation/work 문맥과 작업 디렉터리는 arm별 독립이며 arm 안에서는 준비 세션을 이어간다. 고정 plain→FS 순서의 단일 쌍이다. 161324 FS 대비 총 토큰은 오히려 늘었고, 시간만 약 7.6% 줄었다. 실행 변동과 여러 수정이 함께 있으므로 특정 수정의 인과 효과로 단정하지 않는다.

권한 변경 후 첫 185730은 preflight 합성 진술의 새 reuse 입력 누락으로 모델 호출 전에 실패했다. 합성 진술에 reuseReason과 응답 검사를 추가한 것이 이번 preflight 변경이다. 채점기·정답은 변경하지 않았다.
