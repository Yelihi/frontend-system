# v5: 여러 계층에 걸친 승인 계획 준수

v4의 기존 점수를 보존하고, 별도 과제로 복잡성을 늘렸다. 품질의 정의는 **미리 정한 계약을 최초 구현부터 얼마나 지켰는가**다. FS의 코드 모양과 닮았는지, 문서가 길어졌는지는 점수가 아니다.

새 답변 문서의 evidenceRoutes와 결정 패치를 원자적으로 저장하고, 분석 재사용/제외 이유를 명시하게 했다. 소스·지식 묶음 읽기, 고유 인용의 줄 자동 계산, 실제 MCP 규격에서 생성한 선택형 도움말, 원본을 보존하는 검사 요약과 최종 검사 순서도 보완했다. 최신 타입·린트·78개 테스트, 독립 패키지 검사, v5 실행기 3개와 집계 4개 검사를 통과했다. skill-creator의 Python 검사는 환경의 PyYAML 부재로 실행하지 못했고 스킬 frontmatter와 링크는 별도 확인했다. 185244의 권한 차단, 185730의 합성 preflight 입력 누락은 모델 호출 0회로 보존하며 개선 효과로 집계하지 않는다.

실행 후 `python3 test/evals/fs-comparison/v5/telemetry.py 결과_폴더`로 완료 상태, 누락을 보존한 토큰, 재사용/패치/오류와 제품 해시를 telemetry.json/md에 기록할 수 있다. 이 도구는 원본 판정과 점수를 바꾸지 않는다.

## 과제와 통제 조건

주문 서비스의 HTTP → 저장소 → application controller → React UI와 독립적인 가격 도메인을 연결한다. 변경 가능한 제품 파일은 7개이며, 공용 금액 함수와 기존 money 모듈 등은 보호한다. [계획](scenarios.json)의 모든 요구를 양쪽에 동일하게 제공한다.

- 일반/선물 주문의 할인 정책 차이와 잘못된 수량 검증.
- HTTP 인증·업무·transport 오류의 소유자, 참조 보존, 재시도 금지.
- 두 조회의 완료 순서가 바뀌거나 이전 요청이 늦게 실패하는 경우.
- 상태 스냅샷 및 입력 객체 소유권, 검증 이전 저장 금지.
- 허용된 파일·공개 API·의존 방향을 벗어난 임의 개선 금지.
- 인증 콜백 실패, 목록 갱신 실패에 대한 두 사용자 결정. 질문한 주제에만 답변 제공.

새 세션/임시 Git 프로젝트를 조건마다 생성한다. 한 조건 안에서 prepare → 답변 → work는 같은 세션을 이어간다. 같은 지식 원문 접근, 모델, 시간 제한, 최대 수정 1회를 적용한다. FS만 기존 스킬·MCP 절차를 사용한다. 실제 사용자 판단의 의미를 자동 점수화하지 않는다. 이번 평가도 질문 주제를 명시하므로 **미지의 설계 문제 발견 능력 평가가 아니다**.

[v4 실행기](../v4/run.py)의 격리·대화·사용량 집계 경로를 공유한다. v5는 fixture/채점기/교정만 공급한다. manifest는 과제·실행기·스킬·지식·bundle 해시를 기록한다. 보호 입력 수정, 준비 단계의 제품 수정, FS 절차 생략은 성공이 아니다. 모델 생성 코드는 격리 executor에서만 실행한다. 새 자연어 프롬프트는 비교 대상이라는 설명을 제거했으며 사용자 요구는 숨기지 않는다. 프롬프트 변경도 있어 과거 v4 수치와 직접 성능 증감으로 비교하면 안 된다.

## 측정과 한계

14개 유한 검사: F1~F10, N1/N2, Q1/Q2. 최초/최종 충족 수, 금지·결정 위반, 외부 수정 호출 수를 분리한다. input/cached input/uncached input/output/total과 준비·구현 시간을 기록한다. 누락은 null이며 토큰 배수를 청구 금액 배수로 해석하지 않는다.

F10은 UI 빌드 검사이며 클릭 동작·실제 렌더링 성능의 증명이 아니다. 의존 검사 역시 지정된 AST 구문 범위다. 질문 의미, 잘못된 추상화의 장기 영향, 모든 JavaScript 우회는 `unverified`다. 14/14는 이 14개 검사 통과만 의미한다. 독립 의미 리뷰나 실제 UI 확인 없이 전체 계획·설계 품질이 입증됐다고 보고하지 않는다. 모델 실행 후 점수나 정답을 바꾸지 않는다.

## 실행

레포 루트에서 실행한다. 로그인된 Codex CLI와 기존 frontend fixture 의존성이 필요하다. 일반 터미널 또는 외부 제어기 실행을 승인받은 에이전트에서 실행할 수 있다. 이 대화에서는 `python3 test/evals/fs-comparison/v5/run.py` 실행 허용이 저장돼 직접 실행했다. 다른 세션의 권한은 별도이며 이 문서가 권한을 부여하지는 않는다.

```sh
npm run build
python3 test/evals/fs-comparison/v5/run.py --run --model gpt-6-sol --timeout 600
```

600초는 **양쪽의 각 호출 제한**이다. 준비+구현으로 정상 4회, 수정이 필요하면 최대 6회 모델 호출한다. 복잡성이 늘어 시간 예산을 명시적으로 늘렸으며 v4의 300초 결과와 섞지 않는다. 기본값은 기존과 동일한 300초다. 한 쌍의 파일럿이므로 통계적 우위를 주장할 수 없다. 여러 번 실행하면 별도 결과 폴더가 생긴다. 현재 순서는 plain → FS로 고정되어 순서 편향도 남아 있다.

모델 호출 없이 격리 사전 검사와 교정만 하려면:

```sh
python3 test/evals/fs-comparison/v5/run.py --calibrate-only
```

중첩 sandbox가 차단된 환경에서는 실행기가 멈춘다. 지원되는 외부 제어기 실행 권한을 사용하되, 모델/채점기 격리를 해제하거나 모델 코드를 호스트에서 실행하는 우회 경로는 없다. 저자가 작성한 고정 예제만 사용하는 기능 검사는 별도다:

```sh
python3 -m unittest discover -s test/evals/fs-comparison/v5 -p runner_test.py
node test/evals/fs-comparison/v5/context-reuse.mjs
```
