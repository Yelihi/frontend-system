# 명확한 후속 결정에 대한 계획 수정

복합 질문에 붙은 generic unknown 답변은 이미 제공한 규칙까지 미정으로 읽힐 수 있었다.
원래 결과를 고치지 않고, [같은 후속 결정](../followup-clarifications.md)을 기존 공유
FS 여정과 첫 회차 공유 원문 AI 여정에 각각 전달했다. 각자의 대화만 재개했다.
[사전 프로토콜](../followup-protocol.md)과 실제 상호 경로 접근 거부 검사를 남겼다.

| 조건 | 추가 총 토큰 | 추가 비캐시 입력+출력 | 경과시간 | MCP 실패 |
| --- | ---: | ---: | ---: | ---: |
| 원문 AI | 121,970 | 29,810 | 165.078초 | 0 |
| FS | 556,475 | 32,315 | 501.257초 | 1 |

FS는 이 추가 턴에서 총 처리 토큰 4.56배, 비캐시 입력+출력 1.08배, 시간 3.04배였다.
전체 초기 비용의 새 비교가 아니다. 앞선 질문/답변/계획이 다르고 raw 여정은 이전 회차에서
왔으며, 제공자 캐시도 통제하지 못한다. 수치는 비용 관찰값이지 요금 환산이나 인과 추정이 아니다.

코디네이터가 현재 계획에서 확인한 명시적 의무는 양쪽 모두 다음과 같다.

| 제공한 결정 | 원문 AI 계획 | FS 계획 및 저장 규칙 |
| --- | --- | --- |
| 같은 토큰 교체도 새 문맥; 오래된 read/POST 효과 금지 | 반영 | 반영 |
| 현재 문맥의 401은 superseded read에서도 살아 있는 realm에 전달 | 반영 | 반영 |
| controller 폐기 뒤 View 호출 금지, realm auth는 별도 허용 | 반영 | 반영 |
| 전체 portal 폐기 뒤 host/View 효과 금지 및 새 mount 격리 | 반영 | 반영 |
| 문맥당 만료 통지 한 번, 교체 뒤 새 통지 가능 | 반영 | 반영 |
| POST 자동 재시도 금지 | 반영 | 반영 |

이 표는 문서의 명시적 계약을 대조한 것이며 구현 테스트 통과표가 아니다. 일반적인
설계 품질이나 모든 비동기 경우의 정확성을 점수로 바꾸지 않는다. 보조 모델 리뷰는
[별도 대조 기록](../adjudication.md)에서 확인하며 원문·코디네이터 검토가 우선한다.

FS의 [저장 계약 감사](shared-fs/native-contract-audit.json)는 실제 저장한 7개 필수 규칙과
결정 연결을 읽었다. contractDiagnostics는 빈 배열, 승인 상태는 false, drift는 false이고
독립 plan.md와 저장 projection이 일치했다. 재계산한 hash는 마지막 성공한 save_revision
응답과 일치한다. 따라서 문서만 바꾸고 저장된 의무를 남겨 둔 상태가 아니었다.
MCP의 main source 본문 재읽기 호출은 없었으며 shell도 원본 src 파일을 다시 읽지 않았다.
다만 저장된 draft를 두 번 읽었고 기록 재작성 비용이 남았다. 정확한 호출은
[FS 추적](shared-fs/mcp-trace.json)과 [실행 명령](shared-fs/commands.json)에 있다.

코드·런타임·이전 답변·후속 결정은 모두 보존됐으며 각자의 thread만 재개했다.
모델이 제품 코드를 실행하거나 계획을 승인하지 않았다. 초기 준비 스크립트의 출력 폴더
충돌은 모델 호출 전에 발견되어 수정됐고, [준비 오류](setup-error.json)에 modelCalls:0으로
기록했다. 모델 호출 실패를 감춘 기록이 아니다.

[원문 AI 계획](shared-raw/project/plan.md), [FS 계획](shared-fs/project/plan.md),
[수치·기계적 감사](summary.json)를 함께 볼 수 있다. FS의 근거/규칙 기록 경로가
작동함은 확인했지만, 이 명확한 후속 결정에서는 양쪽 모두 의무를 반영했으므로
FS의 고유한 계획 정확성 우위는 확인하지 못했다.
