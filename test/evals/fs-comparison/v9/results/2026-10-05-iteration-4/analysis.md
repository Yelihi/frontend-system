# v9 보완 4회와 실제 재시험 — 2026-10-05

입력 오류 복구, 구조화 기록 전달, 확정된 결정의 기록 누락을 보완했다. 마지막 두
계획은 완료됐고 확정된 선택의 confirmation/의무 연결 누락이 남지 않았다.
명확한 추가 사용자 결정을 전달한 후속 검사에서는 FS의 저장 규칙 7개와 계획이
일치했고 계약 진단은 0건이었다. **일반 AI보다 정확하거나 전체 토큰을 적게 쓴다는
결과는 얻지 못했다.** 실패·시간 초과·비용 회귀도 아래에 모두 포함한다.

## 구현 변경

1. `fs-plan`의 근거 읽기를 단계화하고, 신선한 main 분석 재사용·canonical plan 복사·
   필요한 필드만 수정하도록 했다. 선택한 결과와 구현 메커니즘을 구분하고 정상/반례
   이벤트 이력, 효과·소유자·생명주기 범위를 점검하도록 했다. 벤치마크 정답을 넣지 않았다.
2. 잘못 인용한 줄은 최대 10개 정확 일치 위치를 진단에 제공한다. 자동으로 근거를
   선택하지 않는다. 재사용 해석이나 이유가 없는 기록은 계속 거부한다.
3. 큰 revision을 `.frontend-system/drafts/<name>.json`으로 제출할 수 있다. 경로,
   symlink, 크기, 허용 필드, 전체 스키마를 검사하고 기존 해시·근거·승인 무효화
   검증을 그대로 적용한다. inline과 file 입력을 섞거나 승인/헤더를 끼워 넣을 수 없다.
4. 도구 목록은 전달용 스키마만 노출하고 상세 `payloadSchema`는 tool-help로 읽는다.
   inline/file 모두 같은 엄격한 전체 Zod 스키마로 검증한다. 입력 스키마 JSON은
   **44,748 → 30,250자(32.4% 감소)**, 도구 수는 45개다. 이는 모델 토큰이나 전체
   도구 메타데이터 크기가 아니며 상세 스키마를 읽는 비용은 남는다.
5. 기존/사용자 결정의 확인 근거, reconsiderWhen, script의 실제 존재와 설정 대기
   표현을 명확히 하고, 확정된 선택의 수정 가능한 진단을 해소하도록 했다.

주요 코드: [draft guard](../../../../../../src/application/revision-draft.ts),
[shared payload schema](../../../../../../src/application/revision-input.ts),
[fs-plan](../../../../../../skills/fs-plan/SKILL.md).
승인·최신성·완료 조건을 완화하지 않았다.

대화로 시작하고, 질문에 해당하는 고정 답변만 전달한 뒤 자기 대화에서 계획을 작성한다.

old/new의 지식 본문·검토 메타데이터·learned index는 최초 파일럿의 동결 바이트를
복사해 일치시켰다. prepare의 add/review/sync 출력은 준비 기록이며, 이후 복사한
코퍼스가 실제 제공 자료다. 반복마다 새 sync의 의미 변환 품질을 측정한 것이 아니다.

두 여정 모두 질문/계획을 완료하고 두 지식의 실제 검색·본문 읽기·결정 연결을 남겼다.
확정된 결정의 confirmation/의무 연결 누락과 없는 script를 즉시 실행하도록 등록하는
저장 오류는 남지 않았다. 미정 결정 관련 진단은 유지했다. 인용 위치 오류와 최초
분석 필드 누락은 여전히 발생했다. **MCP 오류가 모두 사라진 결과가 아니다.**

공유 계획은 compound question의 generic unknown을 이미 답변한 POST 교체 효과까지
넓게 적용했다. 기존 답변표의 unknown 범위가 모호해서 명확한 FS 위반/개선으로
점수화하지 않았다. credential rotation 계획도 미정 효과의 범위를 사용자에게
확인해야 한다. 미정 항목을 늘리거나 줄이는 것 자체는 개선 지표가 아니다.
이번 회차는 알려진 실패의 회귀 검사이며 새 old/raw 대조군과 미사용 사례가 없다.

계획: [공유](shared-new/plan/project/plan.md),
[credential rotation](refresh-new/plan/project/plan.md).
이전 independent의 A→B→A 대응은 1/2회차에 명확해졌지만 3회차에는 generation과
값 비교 설명이 다시 모호했다. 안정적으로 해결됐다고 보고하지 않는다.

## 명확한 사용자 결정의 후속 반영

[같은 추가 결정](followup-clarifications.md)을 FS와 원문 AI에 전달했다. 둘 다 기존의
자기 대화를 재개했고, 원본 결과는 보존했다. 여섯 명시적 의무는 양쪽 계획에 반영됐다.

| 조건 | 추가 총 토큰 | 비캐시 입력+출력 | 초 |
| --- | ---: | ---: | ---: |
| 원문 AI | 121,970 | 29,810 | 165.078 |
| FS | 556,475 | 32,315 | 501.257 |

FS는 총 처리 토큰 4.56배, 비캐시 입력+출력 1.08배였다. 이전 대화/계획 이력과
제공자 캐시가 달라 새 전체 여정의 공정한 비용 인과 비교는 아니다.
FS는 원본 소스 본문을 다시 읽지 않았지만 draft 재읽기와 구조화 기록 비용은 남았다.
필수 규칙 7개·저장 projection·최종 plan.md가 일치하고 계약 진단은 0건,
승인은 false, drift는 false였다. 실제 마지막 save 응답과 재계산 해시도 일치했다.
이는 **결정 → 저장 규칙 → 계획 갱신이 작동한다는 증거**이지 의미적 정확성의 자동 증명이나
일반 AI 대비 품질 우위가 아니다. [후속 상세·양쪽 계획·감사](followup/analysis.md).

## 검토, 검증과 전체 비용

조건명을 가린 packet 10개를 5번 보조 리뷰했다. 서식으로 조건을 추측할 수 있으므로
완전한 블라인드가 아니다. 인용 254건 중 253건이 정확히 일치했으며 대소문자 차이 1건과
source locator 생략 5건을 기록했다. 자동 문자열 일치와 모델 pass가 의미적 정답을
보장하지 않는다. [채택/보류/기각 이유](adjudication.md)를 원문과 대조했다.

- `npm run check`: 타입·린트·Node 회귀 96개 통과.
- `npm run test:package`: 전체 payloadSchema 및 패키지 도구 검사 통과.
- fs-plan 스킬 검사, 실행기 Python 검사 3개 통과.
- 생성 코드 실행/승인 없음. 격리, 원본/런타임/답변 보존, 자기 thread 재개 확인.
- 모델 실제 호출 **48회**: 계획 41 + 후속 2 + 리뷰 5. 완료 턴 43, 사용량 미제공 5.
- 생성 및 후속 알려진 토큰 **18,802,775+**, 리뷰 **667,568**, 총 **19,470,343+**.
  상위 코디네이터의 사용량/시간과 모델 호출 전 준비 실패는 제외했다. 요금 환산이 아니다.
  [전체 호출별 비용](all-attempt-costs.json)에 중단 비용을 0으로 처리하지 않고 보존했다.

이 실험은 작은 TypeScript 프로젝트, 합성 지식 두 편, 한 모델, 사례별 한 실행이다.
축적한 전체 지식의 대표성·대규모 검색·사용자 만족·구현 수정 횟수는 측정하지 않았다.
sync와 trigger의 개별 인과 기여도 분리하지 못한다. 얻은 개선은 입력 전달과 기록
일관성의 국소 개선이다. 전체 비용과 판단 우위를 입증하려면 기록 재전송 비용을 더 줄이고,
모호하지 않은 답변 범위와 미사용 사례에서 같은 후보를 반복 측정해야 한다.
