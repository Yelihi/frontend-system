# 보조 리뷰 대조 기록

리뷰어는 조건 라벨을 받지 않았지만 FS 문서의 서식으로 출처를 추측할 수 있다.
따라서 완전한 블라인드·독립 정답 판정으로 취급하지 않는다. 생성 조건을 아는
코디네이터가 원문과 실제 답변, 별도 저장 기록을 대조한다. 합산 품질 점수는 만들지 않는다.
리뷰 비용은 생성 비용과 따로 기록한다. 이 회차에서 새 리뷰어 정확도 보정 실험은 하지 않았다.

## Batch 1

- P06(세 번째 회차 공유 수정 FS): identity 교체 계약을 따랐다는 평가는 계획의 generation
  설명 및 실제 답변과 일치한다. 소스 commit/owner-answers 경로를 packet만으로 증명할 수
  없다는 지적은 리뷰 범위의 제한이다. 실제 실행 기록과 산출물 감사로 확인할 자료이며
  계획의 허위 주장이나 설계 결함으로 점수화하지 않는다.
- P06의 disposed-controller auth 억제와 superseded-read 401 억제는 검토할 중요한 범위
  선택이다. 리뷰어는 위반으로 분류하지 않았다. 답변의 latest-invocation 규칙은 넓게
  읽을 여지가 있고 실제 expire callback에는 DOM 효과도 있으므로 확정적인 답변 위반으로
  단정하지 않는다. 다만 사용자에게 확인할 가치가 있는 인증/화면 소유권 선택이며
  단순히 ID가 연결되거나 리뷰어가 통과시켰다고 정답이 증명되는 것은 아니다.
- P05(첫 회차 공유 원문 AI): superseded-read 401 우선순위를 열린 결정으로 남긴 것은
  미제공 선택의 보존이다. 이를 단순한 미구현/누락으로 감점하지 않는다. 인용 하나의
  대문자 `The`는 실제 문장 중간의 소문자 `the`와 달랐다. quote-audit의 22/23은 이
  문자열 불일치를 기록한다. 실제 원문에는 해당 열린 결정을 분명히 기술하므로
  인용 형식 오류와 내용 근거의 존재를 구분한다.

이상의 의미 판정은 제한된 문서 검토이며 구현의 실행 결과가 아니다.

## Batch 2

- P03(세 번째 회차 독립 기존 FS)의 `token equality is sufficient only if it covers
  all continuations`는 A→B→A의 중간 이력을 고려하지 않은 메커니즘을 허용한다.
  값 비교 위치를 모든 continuation으로 늘리는 것만으로는 이 문제가 해결되지 않는다.
  리뷰어의 identity answer-followed 판정은 결과 요구를 기술했다는 범위에 한정해서 읽고,
  그 문장이 올바른 구현 메커니즘이라는 보증으로 채택하지 않는다.
- P08(세 번째 회차 독립 수정 FS)은 selected option 비용에 scoped generation을 요구하지만
  rationale에는 token equality가 유효하다고 적는다. 교체 시 변경 감지에 쓰는 비교라면
  generation과 양립하지만, 완료 시 동일성 판정만 뜻한다면 불충분하다. 명확한
  history trace가 없어 엄격한 계획으로서는 해석 여지가 남는다. 확정 실행 오류로
  단정하지 않고, 첫/둘째 회차의 명시적 반례 추적이 항상 재현됐다는 주장도 하지 않는다.
- 처음 quote-audit에서 source 경로가 없는 `artifact:source` 인용 5개를 불일치로
  처리했다. 실제로는 모두 packet의 소스 문자열과 일치했다. locator 처리기를
  고치고 원래 감사 파일도 보존했다. 구체적 파일 위치의 누락은 별도 표시하며
  인용 문자열 오류와 혼동하지 않는다. 리뷰어 원본은 변경하지 않았다.
- 두 계획이 실제로 받은 답변이 다르므로, 미제공 POST/disposal 정책을 열린 항목으로
  둔 P03을 단순히 덜 완성됐다고 감점하지 않는다. 더 많은 문장/의무나 적은 open
  항목 자체가 우위 지표는 아니다.

## Batch 3

- P01(네 번째 회차 공유 수정 FS)은 q4의 마지막 generic unknown을 POST 교체/폐기
  전체에 적용했다. q1과 q4 앞부분은 교체 뒤 모든 old effects를 이미 금지한다.
  좁은 미제공 부분은 폐기 후 auth 효과였지만, 테스트가 전달한 generic 문장은 그
  범위를 밝히지 않았다. 따라서 이 결과로 FS의 명확한 계약 위반이나 회복을
  단정하지 않는다. 같은 명시적 후속 결정을 FS와 원문 AI에 주는 별도 검사로
  이 모호함을 제거했고, 기존 결과와 사용량은 보존한다.
- P01의 `no automated check is presently available`은 package scripts가 없다는
  근거보다 넓다. 프로젝트에 등록된 script가 없다는 사실로 한정해야 한다.
  tsconfig와 환경의 별도 도구 가능성까지 없다고 증명하지는 못했다. 리뷰의
  근거 범위 지적을 채택하며, 실제 테스트가 통과했다는 허위 기록과는 구분한다.
- P07(첫 회차 독립 원문 AI)은 다른 값 교체에 revision을 증가시키고 같은 값
  교체에는 유지하는 메커니즘을 명시했다. 이는 알려진 A→B→A 반례를 다루므로
  그 메커니즘을 FS 고유의 발견으로 주장하지 않는다. 폐기 후 current-session
  auth 선택을 열어 둔 것은 실제 미제공 답변을 반영한다.
## Batch 4

- P04(네 번째 회차 credential refresh FS)와 P02(첫 회차 같은 상황 원문 AI)는
  다른 토큰으로의 교체도 논리적 identity를 바꾸지 않는다는 실제 답변을 계획에 반영했다.
  토큰 값과 요청 소유권을 분리하는 판단은 양쪽에서 관측됐으며 FS 고유 효과가 아니다.
- P04의 POST/이전 credential 401 미정 항목은 넓은 “pending work 유지” 답변과
  효과별 해석이 만나는 부분이다. 리뷰어가 위반을 발견하지 않았다고 그 미정 처리가
  유일한 정답임을 증명하지 않는다. 이미 결정된 효과까지 다시 질문하는지는 더
  명확한 owner 답변으로 확인해야 한다. 열린 항목의 수는 품질 점수가 아니다.
- P02는 disposed-controller 401에 실제 generic unknown을 받았다. 그 선택을
  열어 둔 것은 답변 보존이며, FS보다 적거나 많은 미정 항목을 단순 비교하지 않는다.

## Batch 5 — 명시적 후속 결정

- P09(FS)와 P10(원문 AI)은 동일한 후속 결정에 따라 View와 realm auth의 소유권,
  controller와 portal 폐기의 범위, read/POST의 오래된 문맥 효과를 구분한다.
  양쪽의 명시적 여섯 의무 반영을 원문으로 대조했다. 이는 계획 문서의 준수 확인이지
  구현 실행의 정확성이나 FS 우위 증명이 아니다.
- 이전 질문별 답변은 서로 달랐다. 원문 AI의 indeterminate POST notice와 FS의
  기존 non-OK rejection 유지 차이를 새 공통 후속 결정 위반으로 취급하지 않는다.
  후속 결정은 관련 없는 이전 결정을 유지하도록 명시했다.
- P09의 `none exists today`는 “등록된 test script가 없다”는 앞 문장의 범위로만
  읽는다. 환경에 실행 가능한 모든 검사 도구가 없다는 주장으로 확장하지 않는다.
- FS의 결정/규칙 연결은 별도 native-contract-audit에서 검사했다. 모델 리뷰의
  answer-followed나 인용 일치가 승인·실행 검사·의미적 정답을 대신하지 않는다.

최종 보조 리뷰는 10개 packet, 인용 254건 중 253건 정확 일치다. 한 건은 Batch 1의
대소문자 차이이며, 파일 위치를 생략한 정확 인용 5건도 별도 표시했다.
[인용 감사](reviews/quote-audit.json)와 원래 리뷰 JSON을 모두 보존한다.
