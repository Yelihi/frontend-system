# v9 — 지식이 질문과 설계 판단에 만드는 차이

FS를 **조건부 지식 → 코드 근거 → 질문·선택지 → 사용자 결정 → 계획 계약**으로 평가한다. 구현 코드의 테스트 통과율이나 계획의 길이를 품질 점수로 바꾸지 않는다.

2026-10-05 최초 파일럿 이후 **네 번 보완하고 실제 모델로 재시험했다.** 마지막 후보는 확정된 결정의 기록 누락을 해소했고, 명확한 후속 결정에 대한 저장 규칙·계획 일치를 확인했다. **FS의 고유한 판단 우위나 전체 토큰 절감은 아직 입증하지 못했다.** [네 회차 전체 분석](results/2026-10-05-iteration-4/analysis.md)과 [최초 파일럿](results/2026-10-05-planning-pilot/analysis.md)을 구분해 읽는다.

## 최신 보완과 재시험

- 인용 위치 오류에 정확 일치 후보를 제공하고, 큰 revision은 검증된 draft JSON 파일로 전달한다. 경로·symlink·크기·필드·전체 스키마와 기존 해시/승인 검증은 유지한다.
- MCP 입력 스키마 JSON은 **44,748 → 30,250자(32.4% 감소)**다. 상세 스키마는 필요할 때 읽고 서버는 항상 전체 스키마로 검증한다. 이 수치를 토큰 절감률로 해석하지 않는다.
- 계획 지침은 효과·소유자·생명주기 범위, 정상/반례 이벤트 이력, 확정된 결정의 확인 근거와 규칙 연결을 점검한다. main 분석이 신선하면 재사용하고 저장된 계획 projection을 산출물로 사용한다.

네 회차에서 계획 생성 41회 중 36턴이 완료됐다. 시간 초과 3회와 제공자 용량 오류 2회도 보존했다. 마지막 후보의 공유/credential rotation 두 여정은 모두 완료됐고, 확정된 선택의 confirmation/의무 연결 누락은 남지 않았다. 인용 재시도는 남았고, 미정 선택의 진단은 유지됐다. 이 회차는 알려진 실패의 재시험으로 새 대조군이 없다.

복합 질문에 붙은 generic unknown 답변이 이미 제공한 결정까지 모호하게 만드는 평가 문제도 확인했다. 원본을 고치지 않고 **같은 명시적 후속 결정**을 FS와 원문 AI에 전달했다.

| 후속 결정 반영 | 원문 AI | FS |
| --- | ---: | ---: |
| 명시한 여섯 의무의 계획 반영 | 모두 반영 | 모두 반영 |
| 추가 총 처리 토큰 | 121,970 | 556,475 |
| 추가 비캐시 입력+출력 | 29,810 | 32,315 |
| 추가 경과시간 | 165.078초 | 501.257초 |

FS는 저장 필수 규칙 7개·결정 연결·plan.md가 일치했고 계약 진단 0건, 미승인 상태를 유지했다. 원본 소스 본문을 다시 읽지는 않았지만 기록 재작성 비용은 남았다. 양쪽 모두 제공한 의무를 반영했으므로 FS만의 정확성 우위는 아니다. 서로 다른 앞선 대화와 제공자 캐시 때문에 새 전체 여정의 비용 비교로 해석하지 않는다. [양쪽 계획·후속 상세](results/2026-10-05-iteration-4/followup/analysis.md).

검증은 타입·린트·Node 96개·독립 패키지·스킬 검사 및 실행기 Python 3개가 통과했다. 이번 보완의 실제 CLI 호출은 계획 41 + 후속 2 + 보조 리뷰 5 = **48회**다. 알려진 전체 처리 토큰은 **19,470,343 이상**이며 상위 코디네이터 사용량은 제외한다. 사용량을 받지 못한 5회는 0으로 계산하지 않았다. [호출별 비용](results/2026-10-05-iteration-4/all-attempt-costs.json), [보조 리뷰 원문 대조](results/2026-10-05-iteration-4/adjudication.md), [반복 프로토콜](iteration-protocol.md)을 보존했다.

아래는 **최초 파일럿 당시** 구현·결과다. 후속 수정으로 과거 오류나 비용을 덮어쓰지 않는다.

## 이번에 바꾼 FS

- `fs-plan`은 원문·적용 조건에서 관찰한 코드, 질문/제외한 선택지, 사용자 결정, 규칙/검사로 이어지는 이유를 설명한다. 지식을 읽었다는 사실과 판단이 개선됐다는 주장을 구분한다.
- `get_revision(detail: "influence")`가 저장된 지식 출처 해시·조건·제외 조건, 라우팅 판단, 연결된 결정과 규칙/이슈를 조회한다. 별도 모델 호출이나 필수 기록 필드를 추가하지 않는다.
- 메타데이터가 바뀌거나 사라지면 현재 내용을 과거 근거로 대신 보여주지 않는다. 저장된 연결은 판단의 정확성·인과적 효과·승인을 보장하지 않는다.

구현은 [revision-response.ts](../../../../src/application/revision-response.ts), 도구 연결은 [mcp.ts](../../../../src/mcp.ts), 지침은 [fs-plan](../../../../skills/fs-plan/SKILL.md)에 있다. 승인·최신성·완료 검증 조건을 완화하지 않았다.

## 실험 설계

[사전 프로토콜](protocol.md), [테스트 프로젝트](fixture/README.md), [원문 두 편](corpus), [숨겨진 고정 답변표](answers.json)를 모델 실행 전에 고정했다.

| 조건 | 모델에 제공한 자료·절차 |
| --- | --- |
| 일반 AI | 같은 코드·요청·출력 형식 |
| 원문 AI — raw-K1 | 일반 AI + 원문 두 편 |
| 기본 FS — fs-K0 | FS 스킬·MCP·공통 절차, 실험용 learned index는 비어 있음 |
| 지식 추가 FS — fs-K1 | 기본 FS + 같은 원문에서 등록·검토·sync한 지식 |

K0에도 FS의 일반 지침과 공통 규칙은 있다. 따라서 K0는 모델이 지식을 전혀 모르는 조건이 아니다. K1의 정규화 메타데이터는 이 실험을 위해 작성했으며, 자유형 문서의 AI 자동 변환 품질은 이번 측정에 포함하지 않았다.

테스트 대상은 React에 종속되지 않은 TypeScript 프론트엔드 컨트롤러다. 7개 소스 파일과 README·package.json·tsconfig.json으로 구성하며 두 화면의 검색, 조회, 주문, 인증, 비동기 완료, DOM 생명주기를 포함한다.

- **공유 세션:** 두 화면이 같은 Session을 사용한다. 질문하면, 같은 토큰 문자열의 교체도 새 논리적 문맥이라는 답변을 준다.
- **독립 세션:** 화면마다 Session을 가진다. 질문하면, 같은 값의 교체는 기존 문맥을 유지하고 다른 값은 새 문맥이라는 답변을 준다.

각 조건은 새 코드 사본·새 대화에서 시작한다. 첫 턴에 모델이 자유롭게 질문을 만들고, 코디네이터가 실제 질문과 맞는 고정 답변만 전달한 뒤 같은 대화의 둘째 턴에서 **미승인 plan.md**를 작성한다. 제품 코드는 구현하지 않는다. 질문 주제와 정답 구조를 미리 주지 않는다. 필요한 답변이 없으면 미정으로 남긴다. 코드·런타임·답변 변경 여부와 모델 사용량을 별도로 검사한다.

## 결과

아래 비용은 **두 상황의 완료된 비교 실행 합계**, 즉 조건별 2개 여정·4개 완료 턴이다. 서버 혼잡으로 중단된 두 여정은 같은 초기 코드·런타임의 새 세션으로 다시 실행했다. 원래 실패 기록과 추가 비용은 보존했으며 아래 비교 표에는 최초로 완료된 여정을 사용한다.

| 조건 | 같은 토큰의 의미를 명시적으로 질문/선택지로 다룸 | 질문의 정확한 원문 인용 | 총 처리 토큰 | 비캐시 입력+출력 | 모델·도구 경과시간 합계 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 일반 AI | 0/2 | 25/26 | 347,023 | 89,231 | 429.6초 |
| 원문 AI | 2/2 | 31/31 | 295,942 | 59,142 | 425.4초 |
| 기본 FS | 1/2 | 27/27 | 1,876,354 | 217,346 | 1,026.2초 |
| 지식 추가 FS | 2/2 | 26/26 | 2,471,575 | 178,967 | 1,257.2초 |

질문 횟수는 특정 논점의 **관찰값**이며 종합 품질 점수가 아니다. 일반 AI도 넓은 질문을 통해 관련 답변을 받았다. 인용 일치는 문자열 검사이며 사실 해석의 정확성을 뜻하지 않는다. 일반 AI의 불일치 한 건은 README 인용의 대소문자 차이다. 제공자 프롬프트 캐시는 초기화할 수 없으므로 비캐시 수치의 차이를 최적화 효과로 단정하지 않는다. 토큰 수는 요금 환산이 아니다.

지식 추가 FS는 원문 AI 대비 이 표에서 총 처리 토큰 **8.35배**, 비캐시 입력+출력 **3.03배**, 시간 합계 **2.96배**였다. 질문/근거 기록과 진단 조회까지 포함한 비용이다. 이전 v8의 구현 과제와는 목표·산출물이 달라 수치를 직접 비교하지 않는다.

판단에서 확인한 차이는 다음과 같다.

- 일반 AI의 공유 세션 계획은 확인받지 않은 같은 토큰 교체 정책을 구현 항목으로 정했다. 질문을 더 구체화할 필요가 있는 사례다.
- 원문 AI와 FS는 같은 토큰 교체의 의미를 질문·선택지에서 더 명시적으로 다뤘다. **이 효과는 FS에만 나타나지 않았다.**
- 지식 추가 FS의 독립 세션 계획은 “토큰 문자열 비교로 충분하다”고 판단했다. `A → B → A` 교체에서는 처음 A의 요청을 새 A와 혼동한다. 일반 AI의 독립 세션 계획은 이 반례를 명시했고, 원문 AI는 다른 토큰 교체 때만 증가하는 generation을 제안했다. [반례와 원문 근거](results/2026-10-05-planning-pilot/aba-witness.json)를 보존했다.
- 두 FS-K1 상황에서 두 지식의 검색·본문 참조·판단·결정 연결을 확인했다. 독립 세션에서 전역 인증 상태를 공유하지 않는 조건도 유지했다. 그러나 올바른 연결 기록이 올바른 추론을 보장하지는 않았다.

## 자동 확인과 사람의 검토 범위

자동으로 확인한 것은 입력 보존, 정확한 인용, 자료 해시, sync 검증, 도구 실행, 사용량·대화 ID다. 계획의 의미는 조건명을 제거한 모델 보조 검토와 코디네이터의 원문 대조로 확인했다. 평가자가 FS 표현을 보고 조건을 추정할 가능성이 있으므로 완전한 블라인드는 아니다.

보조 검토의 인용 210건은 전달된 자료와 일치했다. 하지만 평가 자료에 manifest와 FS 내부 기록을 빠뜨려 발생한 오탐은 실제 원본으로 기각했다. 구조 선택을 묻는 질문이 불필요하다는 평가도 사용자 선호에 좌우되므로 자동 감점하지 않았다. [최종 대조 기록](results/2026-10-05-planning-pilot/adjudication.json)에 채택·기각·보류 이유를 구분했다. 모델 평가자를 정답지로 간주하지 않는다.

- FS 자체 검사: `npm run check` — Node 회귀 검사 94개 통과, 타입·린트 통과.
- 새 실행기 검사: Python 단위 검사 3개 통과. 초기 실행 때 2개, 종료 후 공유 격리 경계의 회귀 검사 1개 추가.
- 패키지 검사·스킬 검사 통과. 프로젝트 간 읽기 차단과 실제 MCP 연결도 확인.
- 실제 생성 호출 20회: 18턴 완료, 서버 혼잡 중단 2회. 완료 여정 8개와 재실행 이전 기록 모두 보존.
- 보조 검토 호출 7회: 6턴 완료, 서버 혼잡 중단 1회.
- 전체 생성 호출의 알려진 처리 토큰은 **5,464,724 이상**, 보조 검토는 **799,818 이상**이다. 중단 호출의 사용량은 미제공이므로 0으로 처리하지 않는다. FS를 수정한 상위 대화의 사용량은 이 계측에 포함하지 않는다.

## 해석의 한계와 다음 검증 대상

이것은 작은 합성 프로젝트·작성한 지식 두 편·모델 하나·상황당 완료 실행 한 번의 통제 실험이다. 실제로 축적한 전체 지식, 대규모 검색, 사용자 만족도, 구현 수정 횟수 감소를 입증하지 않는다. 본문 보존과 게시 검증을 통과해도 메타데이터 체크가 원문의 핵심을 충분히 대표하는지는 별도 문제다.

동일 후보가 코드 트리거·요청 검색·파일명 검색 모두에서 검색됐다. 따라서 이번 실험으로 **sync와 trigger 각각의 독립적인 인과 기여는 분리할 수 없다.** 지식 추가 FS의 최초 질문은 6개였지만 환경 재실행에서는 3개였다. 이 변동도 단일 실행을 일반화할 수 없는 이유다.

우선 보완할 지점은 검색 이후의 판단이다. 선택한 조건을 만족하는 예와 반례를 함께 대조하고, 구현 세부안이 승인할 불변조건을 실제로 만족하는지 검토해야 한다. 비용 측면에서는 인용의 위치 확인·구조화 기록 재전송·main/working 구분에서 발생한 MCP 재시도를 줄일 필요가 있다. 이 파일럿에 맞춰 지식이나 정답을 수정한 뒤 같은 결과를 개선 증거로 재사용하지 않는다.

```sh
python3 test/evals/fs-comparison/v9/run.py questions --output "$FS_EVAL_OUTPUT"
```

각 결과의 `questions/project/questions.json`을 읽고 조건별 `answers.json`을 만든다. 숨겨진 고정 답변표에서 해당 질문에 맞는 항목만 고르며 `questionId`, `bankKeys`, 결합한 정확한 `answer`, `mappingRationale`를 기록한다. 이 의미 매핑은 사람/코디네이터 검토 단계다. 키워드로 자동 선택하거나 질문하지 않은 답변을 보충하지 않는다. [이번 실행의 예](results/2026-10-05-planning-pilot/shared-ordinary/answers.json)를 참고한다.

```sh
python3 test/evals/fs-comparison/v9/run.py plan --output "$FS_EVAL_OUTPUT"
python3 -m unittest discover -s test/evals/fs-comparison/v9 -p 'test_*.py'
```

원문·질문·전달한 답변·계획·rubric을 조건명 없이 준비한 보조 검토 packet은 다음으로 검토할 수 있다. 원본의 package.json·tsconfig.json도 포함하고, 내부 FS 기록은 별도 감사한다.

```sh
python3 test/evals/fs-comparison/v9/review.py path/to/packet.json \
  --experiment-root "$FS_EVAL_OUTPUT" --output "$FS_EVAL_OUTPUT/reviews/new-review"
```

같은 결과 폴더를 덮어쓰지 않는다. 실행 중 런타임·입력·판정 기준을 수정하지 않는다. 실패 후 재실행은 별도 기록에 남긴다. 이번 재실행은 `results/.../recovery*`와 [환경 복구 기록](results/2026-10-05-planning-pilot/environment-recovery.md)에 있다.

링크가 열리지 않으면 저장소 터미널에서 `less test/evals/fs-comparison/v9/README.md`로 읽을 수 있다.
