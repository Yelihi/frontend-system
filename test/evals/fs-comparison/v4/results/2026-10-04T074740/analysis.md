# v4 단순화 후 실제 구현 비교 — 2026-10-04

이번 실행은 한 사례가 아닌 전체 세 사례다. `gpt-6-sol`, 사례별 1회, 호출별 300초 제한으로 모델을 12회 호출했다. 매니페스트의 bundle·skills·references·mandatory-rules 해시가 분석 시점의 수정본과 일치한다. 격리 사전 검사와 교정을 통과했으며 일반 AI/FS 모두 최초 구현 호출에서 외부 계약 검사를 통과했다. 추가 수정 호출은 없었다.

이번 준비 시간은 각각 179.996 / 292.389 / 214.956초다. existing-good은 제한까지 약 7.6초의 여유만 남아 여러 번 반복해도 안정적이라고 단정할 수 없다. 단순화 후 정상 여정이 관찰됐지만 단일 재실험으로 개선의 인과성·재현성을 통계적으로 증명하지는 않는다.

세 FS 사례 모두 실제로 contextId를 사용해 계획을 저장했고 `request-policy-boundaries`를 apply로 연결했다. 사용자 결정과 승인, 작업 시도, 프로젝트 검사, 의미 검토, 완료 저장이 관찰됐다. 따라서 이번은 FS 경로를 생략한 일반 코딩 결과가 아니다. 다만 지식 적용 기록이 있다는 사실만으로 그 지식이 없었을 때보다 좋은 코드를 만들었다고 증명되지는 않는다.

## 남은 비용과 오류

| 단계 합계 | 일반 AI 토큰 | FS 토큰 | 일반 AI 시간 | FS 시간 |
| --- | ---: | ---: | ---: | ---: |
| 준비 | 301,877 | 1,720,563 | 177.967초 | 687.341초 |
| 구현 | 722,245 | 4,167,579 | 470.456초 | 669.657초 |

구현 단계에도 준비 대화와 기록이 이어지므로 큰 문맥을 반복 처리한다. 실제 shell 호출은 일반 AI 63회, FS 66회로 비슷했고, FS에는 MCP 86회가 추가됐다. 이 수치는 추가 절차를 보여주지만 토큰을 도구 스키마·문서·기록별로 정확히 배분한 측정은 아니다.

FS의 전체 실패 응답은 7회(준비 6, 구현 1)다. 아직 잘못된 verification enum, 너무 큰 get_revision.limit, absence의 scope 누락, 존재하지 않는 의미 트리거, 라우팅에서 누락된 package.json 인용, 완료 저장의 검사 ID 오타가 있었다. 모두 수정 후 진행됐다. 특히 누락된 파일 오류는 이제 경로와 허용 범위를 알려주어 재분석 후 계획 저장에 성공했다.

기본 맥락 응답은 줄었지만 duplicated에서 `detail:full` 약 47,210자를 한 번 요청했다. `save_revision`·`approve_revision`·`get_revision`도 계획별 약 1.1만~1.9만 자를 반환했고, existing-good에서는 같은 크기의 get_revision 응답을 두 번 읽었다. 다음 비용 개선 후보는 저장·승인 응답의 중복과 구현 시 필요한 문맥의 범위다. 사용자 결정·근거·검증을 생략해 비용을 줄이면 안 된다.

## 코드에서 관찰한 차이와 한계

- duplicated는 두 조건 모두 27행의 요청 client로 계약을 구현했다. existing-good의 client는 양쪽 모두 원본 바이트를 보존했다.
- different-policies의 일반 AI는 transport가 중첩 입력을 바꾸는 경우까지 보호하는 재귀 복사 로직을 추가했고 FS는 얕은 복사를 사용했다. 각각 51행/27행이다. 어느 쪽이 적절한지는 transport의 입력 변경 권한이라는 추가 계약에 달려 있다. 줄 수만으로 우열을 채점하지 않는다.
- FS는 두 사례에서 UI 동작 테스트를 추가했고 일반 AI는 다른 한 사례에서 추가했다. React 대역을 통한 핸들러 검사이며 실제 렌더링·브라우저 검증과 다르다. 테스트 개수만으로 품질 우위를 주장하지 않는다.
- 일반 AI의 두 수정 client는 인증 콜백이 실패해도 unauthorized 오류를 던지도록 했고 FS는 콜백을 직접 호출했다. 콜백 실패 시의 요구는 이번 채점에 포함되지 않았다. 사후에 새 정답으로 추가해 기존 통과를 뒤집지 않는다.

이번 점수는 제한된 외부 계약 검사다. 실행 결과의 `semanticReview: unverified`는 그대로 유지하며 FS 자체 의미 검토를 독립 평가로 계산하지 않는다. 모델 1개·세 사례 각 1회이므로 일반화하지 않는다.

## 결론과 다음 검증

**FS 절차가 실제로 완료되는 것은 확인했다. 동일한 확정 계획을 구현하는 상황에서의 추가 가치는 아직 확인되지 않았으며 처리량과 시간은 증가했다.** 이 부정적인 비용 결과는 그대로 보존한다.

사용자의 주된 목적은 좋은 지식으로 중요한 질문과 선택지를 만들고 더 적합한 계획을 수립하는 것이다. 이번에는 계획을 양쪽에 미리 확정해 주었으므로 그 효과는 측정하지 않았다. 질문·계획 실험을 별도 지표로 진행하되, 유리한 결과가 나와도 이번 동일 계획 구현 비용을 숨기거나 대체하지 않는다. 준비 비용의 반복 작업 간 재사용 효과도 별도 누적 여정으로 확인해야 한다.
