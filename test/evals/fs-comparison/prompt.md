기존 주문 화면에 수량 선택 기능을 구현해주세요. 아래 범위의 설계·구현·테스트를 승인합니다. 필요한 구현 계획은 이 요구사항 안에서 정하고 실행까지 완료해주세요.

요구사항:
1. 기존 첫 화면과 서버에서 렌더링하는 상품 설명을 유지합니다.
2. 접근 가능한 이름이 `Quantity`인 숫자 입력을 추가합니다. 기본값은 1이며 1~10의 정수만 주문할 수 있습니다. 빈 값·0·음수·소수·11 이상은 전송하지 않습니다.
3. 단가는 12,000원입니다. 접근 가능한 이름이 `Total`인 output 요소에 현재 수량의 합계를 원 단위로 표시하고, 유효한 수량 변경 즉시 갱신합니다. 유효하지 않은 입력은 합계로 오인되지 않도록 처리합니다.
4. 기존 `Place order` 버튼과 성공 시 `Order received` 메시지는 유지합니다. 선택한 수량을 `/api/orders`에 JSON `{quantity: 수량}`으로 POST합니다.
5. 요청 중에는 수량 입력과 제출 버튼을 비활성화하고 중복 전송을 막습니다. 실패하면 접근 가능한 오류를 표시하고 수량을 보존합니다. 재시도할 수 있어야 하며 성공하면 이전 오류가 사라져야 합니다.
6. UI뿐 아니라 기존 `createOrderSubmitter`와 서버 API도 1~10 정수 조건을 검증합니다. API는 잘못된 JSON, 빠진 수량, 문자열 수량, 범위를 벗어난 수량을 400으로 거부하고 유효한 요청은 기존 성공 응답을 유지합니다.
7. 키보드로 수량 변경과 주문이 가능해야 하며, 360px 폭에서도 가로 스크롤 없이 사용할 수 있어야 합니다. 정상 주문·실패 후 재시도에서 브라우저 런타임 오류가 없어야 합니다.

작업 조건:
- 기존 기술·의존성·lockfile·검사 설정과 기존 테스트는 보존합니다. 필요한 테스트 파일은 추가할 수 있습니다. 기존 API와 도메인 모듈의 위치·export 이름은 유지합니다.
- 기존 프로젝트의 검사 명령을 사용해 구현을 확인하고, 실제 실행한 결과와 미확인 범위를 짧게 보고해주세요.
- 별도 모델이나 하위 에이전트, 웹 검색, 외부 서비스, 패키지 설치를 사용하지 않습니다. 프로젝트와 제공된 도구 자료만 사용합니다.
- 다른 작업 디렉터리, 개인 설정, 과거 대화와 실행 기록을 읽지 않습니다. 이 프로젝트 밖의 파일을 수정하거나 커밋·푸시하지 않습니다.
