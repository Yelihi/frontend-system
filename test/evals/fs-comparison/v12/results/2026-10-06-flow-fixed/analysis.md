# 첫 보완판 — 오류는 감소, 토큰 절감은 미확인

동일 프로젝트·프롬프트·지식·의미 기준으로 FS 분석/계획 4회를 새 세션에서 실행했다.
4회 모두 산출물 저장과 소스/런타임 격리 검사를 통과했다. 계획은 미승인이다.

| 사례 | 단계 | 총 토큰 | 비캐시 입력+출력 | 초 | MCP 오류 |
| --- | --- | ---: | ---: | ---: | ---: |
| 요청 | 분석 | 1,239,848 | 74,280 | 391.002 | 2 |
| 요청 | 계획 | 1,794,484 | 76,468 | 296.104 | 2 |
| 스타일 | 분석 | 819,439 | 105,967 | 337.546 | 2 |
| 스타일 | 계획 | 1,936,869 | 89,317 | 304.547 | 2 |

합계 5,790,640 총 토큰 / 346,032 비캐시 입력+출력, MCP 오류 8건.
첫 실행 FS의 5,728,903 / 315,271 / 21건과 비교하면 오류는 줄었지만 총 토큰과
비캐시 입력+출력은 늘었다. 캐시·샘플링의 영향이 있어 개별 수치를 일반화하지 않는다.

## 확인된 동작과 남은 문제

- 두 계획 모두 새 호출자로 인한 stale을 조회하고 흐름/개선 항목을 갱신했다.
  계획의 과거 기록 해시와 ID 연결이 일치한다. 상세는 [기계적 감사](mechanism-audit.json).
- 요청 계획은 서비스 토큰/상호작용 인증 경계, 입력 보존, 재시도 금지, 기존 수량
  규칙, 이후 편집 보호와 edit-then-revert를 구체화했다. 스타일 계획은 새 호출자,
  필수 두 축·네 조합, 기존 팔레트·Indicator 제외를 보존했다.
- 수량 확대 질문은 사라졌지만 요청 계획에 범위 밖 logging-sink가 open으로 남았다.
  이슈 연결은 없지만 현재 전체 계획 승인 조건은 여전히 충족하지 못한다.
- 스타일의 마지막 contractDiagnostics는 비어 있지만 실행 검증은 아니다. 추가 예정
  style:check와 style-policy.json이 없으며 기록된 ../../runtime 경로도 프로젝트
  루트 기준 실제 helper 위치와 다르다. 구현 준비가 끝났다고 판단하지 않는다.
- 요청 코드의 query 변경으로 Tailwind 팀 정책이 request-search 후보에 포함됐다.
  언어 검색의 거짓 양성이며, 적용 없이 제외 조사 비용이 발생했다. 지식 도달과
  적합한 판단은 구분해야 한다.

## 추가 보완의 근거

분석 4건의 오류는 scope에 정확한 파일이 아닌 범위를 전달해 발생했다. 오류가
어느 기록/경로인지 말하지 않아 모델이 내부 번들을 읽었다. 이후 소스는 해당 ID와
누락 경로, scope도 의존 파일이라는 설명을 반환하며 회귀 검사로 확인한다.

계획 4건은 조사 결과 누락 또는 owner confirmation이 인용의 정확한 부분 문자열이
아닌 오류였다. 검증을 유지하고 입력 스키마의 조건 설명을 추가했다.

응답량 감사에서는 전체 context 선조회 및 반복 schema 조회를 확인했다. 후속판은
summary부터 시작하고 필요한 관계만 추가하도록 명시하며, 계획 스키마의 중복 정의를
표준 로컬 $ref로 공유한다. 스키마는 22,065 → 14,769자이며 규칙/필드 삭제가 아니다.
실제 토큰 변화는 다음 별도 동결 실행으로 확인한다. 검사 경로를 프로젝트 루트에서
확인하도록 지침도 보완했다. 이전 출력이나 비용을 대체하지 않는다.

기록 해시·연결·조사 결과는 해석의 진실성을 증명하지 않는다. 이번에는 제품 구현이나
브라우저 실행이 없으며, 일반/동일 지식보다 판단 품질이 우월하다고 결론 내리지 않는다.
