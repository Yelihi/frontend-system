# 첫 실행 결과와 수정 근거

실제 모델 12회가 종료됐습니다. 지정 위치의 산출물 기준으로 10/12회 완료이며,
두 위치 불일치에도 문서와 사용량은 모두 남아 있습니다. 판단 품질과 파일 위치
오류를 구분합니다. FS 네 호출은 저장까지 끝났지만 계획은 미승인이며 준비 조건이 있습니다.

## 의미 검토

| 관찰 | 일반 AI | 동일 지식 AI | FS |
| --- | --- | --- | --- |
| 새 요청 소비자와 서비스 토큰 경계 | 반영 | 반영 | 계획·흐름 버전에 반영 |
| 신규 Button 호출자, 필수 props, palette, Indicator 제외 | 반영 | 반영 | 반영 |
| 수량 도메인 확대 | NaN/비유한값 거부 추가 | 기존 predicate 보존 | 기존 predicate 보존 |
| 이전 분석 재검토 | 문서 수정 | 문서 수정 | 두 프로젝트 모두 stale 감지·갱신 |
| 범위 밖 미정 사항 | 삽입/동시성 등 제외 | 수량 도메인 등 제외 | 수량 질문을 현 이슈의 open 결정에 연결해 승인 차단 |

수량 도메인은 작성자가 수행한 정성 검토입니다. 주어진 계약은 검증 실패의 부작용을
금지하지만 NaN을 새로 거부하라고 지정하지 않았습니다. 일반 AI는 이를 좁은 보완으로
판단해 요청 경계 리팩터링에 동작 변경을 추가했습니다. 동일 지식 AI와 FS는 기존
규칙을 유지하고 새로운 도메인 판단으로 남겼습니다. 한 사례의 범위 통제 차이이며,
동일 지식 AI도 같은 구분을 했으므로 FS 자체의 인과적 우위를 뜻하지 않습니다.

- [일반 AI 요청 계획](request-ordinary/plan/project/plan.md): “Reject values below one and non-finite values”
- [동일 지식 AI 요청 계획](request-raw-K1/plan/project/plan.md): “Keep the existing quantity rule unless product intent is supplied”
- [FS 요청 계획](request-fs-K1/plan/project/plan.md): “do not broaden validation … without an owner answer”
- [일반 AI 스타일 계획](styles-ordinary/plan/project/plan.md)
- [동일 지식 AI 스타일 계획](styles-raw-K1/plan/project/.eval/plan.md)
- [FS 스타일 계획](styles-fs-K1/plan/project/plan.md)

FS 스타일 계획은 필요한 자동 검사를 갖추지 못했습니다. 제공 프로젝트에 실행 환경과
스크립트가 없고 설치/구현도 금지되어 있으므로, 검증 준비와 실행 결과를 구분해야 합니다.
누락 검사를 통과로 바꾸거나 승인하지 않았습니다. [연결 감사](mechanism-audit.json)에
진단을 기록했습니다. FS 요청 계획의 범위 밖 open 질문은 별도의 보완 대상입니다.

## 확인한 결함과 보완

1. Markdown 분석 보고서 생성을 새 코드 소비자로 판단했습니다. 코드/설정/데이터
   발견과 문서 포함 전체 발견을 구분하고 명시한 요구 문서는 항상 해시를 확인합니다.
2. main 스냅샷 흐름에 개선 항목을 붙이지 못했습니다. 같은 스냅샷을 인용하면 허용하고
   새 작업 답변을 오래된 main 인용과 섞는 것은 계속 거부합니다.
3. confirmation 한 필드 수정에 분석 전체를 재전송했습니다. 프로젝트 분석도
   JSON draftFile로 저장하고, 오류 필드만 수정할 수 있게 했습니다.
4. 상세 분석 세 건의 일괄 조회를 거부했습니다. 최대 세 건·공유 분량 제한으로 읽고,
   큰 기록은 파일 경로와 생략 이유를 반환하도록 바꿨습니다.
5. 중복 ID·조사 조건 오류의 위치가 불분명했습니다. 해당 컬렉션/ID/질문을 표시합니다.
   조건을 억지로 바꿔 통과시키지 말고 실제 근거를 재검토하도록 안내합니다.
6. 범위 밖 미래 질문이 현재 이슈를 막았습니다. 영향을 주지 않는 미정 사항은
   deferred finding 또는 링크 없는 제외 결정에 두도록 지침을 수정했습니다.

잘못된 인용, 빠진 후보 판단, 부적절한 적용 조건, 존재하지 않는 검사 스크립트는
모델의 초안 오류로도 관측됐습니다. 이를 거부한 것은 필요한 동작입니다.
검증을 느슨하게 해서 오류 수를 낮추지 않았습니다.

## 위치 복구와 한계

일반 AI 요청 분석은 `.eval/analysis.md`, 동일 지식 AI 스타일 계획은 `.eval/plan.md`에
저장됐습니다. 원래 audit의 unverified는 보존했습니다. 요청 분석은 같은 바이트를
루트로 복사한 [위치 복구 기록](request-ordinary/artifact-recovery.json)을 남겨 다음
단계를 이어갔습니다. 추가 모델 호출이나 내용 수정은 없습니다.
[실행기 보완](harness-amendment.json)은 이 위치 복구만 허용하며 코드·계약·프롬프트·
의미 평가 기준을 바꾸지 않았습니다.

두 작은 프로젝트, 한 모델, 조건당 1회입니다. 전체 코퍼스를 제공했지만 자연어 원문의
자동 변환 정확도, 대규모 프로젝트 시간, 실제 구현 품질이나 브라우저 런타임 성능을
입증하지 않습니다. 사례 작성자가 평가했으며 블라인드 검사가 아닙니다.
수정본은 같은 입력·지식·기준으로 FS만 후속 검증합니다. 실행 변동도 있으므로
개선을 통계적으로 일반화하지 않습니다.
