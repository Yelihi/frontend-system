# v7: 기능은 같고 작성 규칙은 다른 코드

## 사전 고정한 평가 목적

v6 운영 콘솔(4 도메인, 32 파일)의 기능을 보존하고 3개 변형 컴포넌트와 테마를 추가한다. 35 JS/JSX 파일과 theme.css를 제공한다. 변경 범위는 UI와 테마이며 핵심 도메인/요청/보상 코드는 보호한다. 파일 수가 큰 것과 변경 과제가 복잡한 것은 구분한다.

초기 코드는 동작과 클래스 집합이 정상이나 고정 클래스 객체, CVA 대신 삼항식 기반 다중 prop 스타일링, 미확정 테마 전략이 있다. 사용자가 채택한 팀 규칙을 지식에서 읽고 적용하며, 테마만 질문한다. 일반 데이터 객체, 단일 boolean 토글, CVA 설정 객체는 금지하지 않는다. 객체 매핑 자체는 Tailwind 오류가 아니다.

## 통제와 판정

- 같은 초기 코드, 계획, 지식, 설치된 의존성, 공개 lint:styles/test/build와 시간 제한을 두 arm에 제공한다. FS arm만 FS 절차/MCP 사용을 지정한다.
- 각 arm은 새 임시 프로젝트와 새 모델 세션에서 시작한다. prepare→사용자 답변→work만 같은 대화를 재개한다. 질문 단계 제품 변경은 실패다.
- 외부 오라클은 FS 검사기를 호출하지 않는 별도 AST/동작 검사를 사용한다. 모델 결과는 제한된 실행기로만 실행한다. 허용 범위·입력·런타임 변경을 검사한다.
- 93개 검사: 기존 v6 계약 69개, 팀 작성 규칙 17개, 새 변형/props/CSS 동작 5개, 테마 결정 2개. 기능과 작성 규칙 점수를 별도 보고한다. FS 완료 절차도 별도 판정한다.
- 교정은 정상 4개와 변이 9개다. CVA 결과 지역 변수와 CSS 주석은 정상 사례로 포함한다. 클래스 객체/삼항식 변이는 기능 검사를 모두 통과하면서 스타일 검사에서 실패해야 한다. 사용되지 않는 CVA, 이벤트 누락, 미승인 테마도 검출한다.
- 최종 통과만 보고하지 않고 첫 결과, 수정 재시도, 전체 토큰(캐시 포함), 비캐시 입력+출력, 시간, 도구 오류를 보존한다. 개선판을 변경하면 다른 manifest로 구분한다.

## 한계

하나의 모델·한 과제의 소표본이다. 공개 정책과 lint를 두 arm에 제공하므로 일반 AI도 모두 통과할 수 있다. 질문할 topic을 프로토콜에 명시하므로 질문의 자율 발견/품질 우위를 입증하지 않는다. 같은 파일 CVA 정의로 범위를 한정한다. 렌더/이벤트 모형과 실제 Tailwind 컴파일을 사용하지만 브라우저 픽셀·접근성 전체를 검증하지 않는다. CSS 생성 검사는 명시된 후보 클래스를 사용하며 자동 소스 탐색 성능 검사가 아니다. 팀 규칙 점수는 보편적인 코드 품질 점수가 아니다.

유료 모델 호출 전에 React 렌더 모형의 children 처리 오류를 바로잡았다. props.children을 위치 인자가 없을 때 보존한다. v6 오라클 파일은 수정하지 않았고 v7에서만 보정했다.

## 실행

```sh
npm ci --prefix test/evals/fs-comparison/v7/toolchain
npm run check
python3 test/evals/fs-comparison/v7/runner_test.py
python3 test/evals/fs-comparison/v7/run.py --calibrate-only
python3 test/evals/fs-comparison/v7/run.py --run --model gpt-6-sol
python3 test/evals/fs-comparison/v7/telemetry.py <results-directory>
```

단계별 2400초를 두 arm에 동일하게 적용한다. 외부 실행 권한과 별도로 모델/채점 격리는 유지한다. results/의 manifest와 summary가 실제 실행 근거다. validation/authored-calibration.json은 모델 호출 0회의 검사기 교정 결과이며 AI 비교 결과가 아니다.

총 5개 paired run·20번 모델 호출이다. 4쌍은 완주했고 C1의 FS work는 서비스 capacity 오류로 중단됐다. C1과 C2의 manifest는 동일하다. C1의 시간은 중단까지 관측한 시간이며 완료 시간은 아니다. 확인된 처리 토큰 하한은 11,362,508이며, 중단된 work의 usage가 없으므로 전체 비용 합계는 알 수 없다. 실패를 삭제하거나 0토큰으로 처리하지 않았다.

최종 D의 FS는 일반 AI보다 총 처리 토큰 **4.66배**, 비캐시 입력+출력 **2.66배**, 시간 **2.14배**였다. 최초 A의 FS보다 총 토큰 8.9%, 시간 18.1%는 감소했지만 비캐시 입력+출력은 1.2% 늘었다. 따라서 **일반 AI 대비 준수/비용 우위나 일관된 비용 절감을 입증하지 못했다.** 같은 기준을 두 쪽에 제공하면 일반 AI도 이를 잘 적용한다. 캐시 포함 처리량을 금액으로 해석하지 않는다.

반복에서 수정한 항목은 scoped lint/typecheck의 기본 검사 누락, 20개 초과 소스 요청의 페이지 처리, 내부 discovery 검색어 길이 초과, 정상 조건식/클래스 연결의 검사기 오탐, 상대 경로로 변형 검사를 건너뛰는 구성 문제다. 코드/검사/승인/인용 검증을 약화하지 않았다. B에서는 검사 5→3회·build 3→1회가 관측됐지만 D는 검사 4회·build 2회였다. 모델의 작업 순서 편차와 중복은 남아 있다.

FS는 Tailwind 지식을 실제로 read_learned_knowledge로 읽고 apply로 채택해 lint:styles 및 정책에 연결했다. A의 main 소스 읽기 41개 구간은 모두 달랐으므로 이번 높은 비용을 동일 소스 반복 읽기만으로 설명할 수 없다. 첫 프로젝트 분석, 지식 판단, 구조화된 계획/근거 및 완료 절차의 처리량이 추가된다. 장기간 유지보수에서 이 초기 비용을 회수하는지는 이 실험으로 증명하지 않는다.

## 교정 및 재채점

초기 교정 11개 이후 정상 CVA 결과 지역 변수와 CSS의 “no dark mode” 주석이 오답 처리되는 것을 별도 authored audit에서 발견했다. 독립 오라클을 수정해 정상 4개·위반 9개, 총 13개를 통과시켰다. 이전 완료 구현 7개를 제한된 실행기로 재채점했고 진단/93점 결과가 모두 같았다. 원본 grade/summary/usage는 덮어쓰지 않았고 중단된 FS turn은 재채점하지 않았다. D는 수정 오라클로 직접 평가했다.

`validation/*-false-positive-audit.json`은 수정 전 발견 근거이며 `validation/authored-calibration.json`은 수정 후 교정이다. 어느 것도 실제 모델 비교 점수가 아니다. 각 이전 결과의 `regrade/summary.json`은 재채점 근거다.
