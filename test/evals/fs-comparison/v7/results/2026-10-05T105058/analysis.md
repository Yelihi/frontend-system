FS는 Tailwind 지식을 apply로 채택하고 필수 규칙/검사에 연결했다. baseline에 lint:styles/test, 개발에 test/lint:styles, 별도 build, 최종 delivery가 기록됐다. 검사 호출은 4회, build는 2회다. 완전한 중복 제거라고 주장하지 않는다. 36개 제품 파일 중 33개는 일반 AI와 바이트 단위로 같으며 보호된 기능 코드 비중이 크다.

FS의 총 처리 토큰은 일반 AI의 4.66배, 비캐시 입력+출력 2.66배, 시간 2.14배다. A 대비 총 토큰 -8.9%, 시간 -18.1%지만 비캐시 입력+출력 +1.2%다. 일관된 비용 절감 또는 일반 AI 대비 구현 우위를 입증하지 못했다. 같은 지식과 공개 checker를 제공한 조건이며, 지식 없는 일반 요청과 FS 전체 제품의 비교는 아니다.

D에는 scoped lint 발견, 소스 페이지 처리, 내부 검색어 예산 수정, 조건식/완전한 클래스 연결/상대 경로 정책 검사의 보완이 들어 있다. CVA 결과 지역 변수와 테마 주석을 잘못 거부하던 독립 오라클도 수정했다. 정상 4개·변이 9개 교정 및 격리 preflight 후 모델을 호출했다. 이전 완료 구현 7개도 수정 오라클로 제한된 재채점을 수행했고 기존 진단/점수가 유지됐다.

브라우저 픽셀/실제 React 스케줄러/일반적인 유지보수성/자율 질문 발견은 이 결과의 증명 범위가 아니다. API/동작/클래스 조합·실제 Tailwind 컴파일과 정해진 코드 규칙을 확인했다. semantic review 기록의 존재와 독립적인 의미 품질 평가는 구분한다.
