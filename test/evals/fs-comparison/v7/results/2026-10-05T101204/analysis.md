# v7 B — scoped lint 발견과 개발 검사 범위 수정

과제·오라클·질문·답변·시간 제한은 A와 같다. 런타임의 lint:/typecheck: 발견 및 기본 검사 선택, fs-work의 불필요한 조기 build 억제 지침만 보완했다.

FS의 baseline은 이번에 lint:styles 실패와 test 통과를 기록했다. 이후 test/lint:styles, 최종 delivery만 실행해 검사 5→3회, build 3→1회로 줄었다. 총 토큰은 A 대비 10.1%, 시간 24.7% 감소했지만 비캐시 입력+출력은 6.3% 증가했다. 일반 AI 대비 총 토큰 3.22배이며 준수 점수는 같다. 이 단일 비교를 일반적인 토큰 절감으로 주장하지 않는다.

MCP 오류는 read_project_source에 23개 파일을 요청해 20개 입력 제한을 넘긴 1회다. 모델은 뒤이어 분할 읽기로 복구했다. 제품 결함이나 권한 승인 오류가 아니다. 이후 C는 요청 목록을 페이지로 반환하되 실제 읽기 20개/24,000자 한도를 유지한다. 지식/필수 규칙/승인/완료 검증은 유지한다.

일반 AI의 npm test 실패는 테마 구현 전에 새 테스트가 기존 @utility를 거부한 결과였다. 초기 lint 실패도 의도된 위반 발견이다. 이를 최종 제품 오류나 외부 수정 재시도로 세지 않는다. FS의 CSS rg 종료 1은 출력 탐색 미일치였다. 외부 수정 재시도는 양쪽 0이며, 모든 원본 이벤트를 보존했다.
