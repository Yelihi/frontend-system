## 1차 수정 — 정책 입력과 완료 연결

실험 후 작업 트리에 다음 수정을 적용했다. **아래 36회 결과는 수정 전 스냅샷 결과이며, 수정판의 토큰·품질 효과는 아직 재측정하지 않았다.**

- `save_revision`: check command·guard hash를 생략하면 실제 스크립트 본문·파일 해시를 고정한다. 명시한 값과 기존 정책은 임의 갱신하지 않는다. 승인 시 명령·검증 파일의 변경을 검사한다.
- 정책의 의미 ID는 `R1`·`mandatory:common:…`·한국어 사용자 규칙을 수용한다. 파일 경로에 쓰이는 기록·소스·제안 ID 제한은 유지한다.
- `save_execution`: 승인된 이슈의 제목·파일·의존성·필수 검사 목록을 생략할 수 있다. 서버가 계약을 채우며, 명시적 계약 변경·오래된 근거·시도 제한 검사는 유지한다.
- 검사 기록은 `coverage`에 필수 스크립트 결과를 명시한다. 기존 `full` 의미는 유지하고, 동일 delivery 기록을 단계 검사와 최종 검사에 함께 연결하는 방법을 MCP 설명과 워크플로 문서에 추가했다. 자동 검사 생략이나 캐시는 추가하지 않았다.

회귀 검사는 `test/plans-project.test.ts`의 실제 MCP 입력→정책 고정→승인→축약 실행→delivery→완료 경로와, 잘못된 명령·변경된 검증 자산·계약 변경·ID 경계를 포함한다. 실행 명령은 저장소 루트의 `npm run check`다. 타입 검사·lint·47개 테스트가 모두 통과했다. `npm_config_cache=/tmp/fs-policy-npm-cache npm run test:package`로 패키지의 독립 MCP 실행도 통과했다(기본 npm 캐시 쓰기 권한이 없어 임시 캐시 사용). 생성된 실험 결과는 저장소 lint에서 제외한다.

[기존 계약 재현 스크립트](probe-contracts.mjs)는 저장된 수정 전 소스 해시가 일치할 때만 실행한다. 원 진단 JSON과 모델 결과는 덮어쓰지 않는다. 1차 수정 이후의 반복 맥락 축소·검색 관련성·반례 검토 절차 개선은 [v3 준비](../v3/README.md)와 [작동 설명](../../../../docs/fs-runtime-guide.md)에 따로 기록한다. 보호된 테스트의 통과가 요구사항 전체 충족을 보장하지 않는 한계도 남아 있다.

## A — 같은 산출물의 절차 비용

**이 조건에서 FS의 토큰 절감은 입증되지 않았다.** 사용량을 양쪽 3회 모두 받은 Sol은 FS 총 토큰 중앙값이 일반의 **3.85배**로, 절감률은 **−284.7%**였다. 비캐시 입력 중앙값도 일반 62,715 → FS 100,639로 증가했고, 적격 완료는 일반 3/3·FS 2/3이었다. Astra와 Luna의 FS는 시간 초과로 사용량이 누락돼 3회 중앙값·절감률을 계산할 수 없다. 사용량을 받은 회차만 골라 전체 결과로 제시하지 않는다.

**현 스냅샷의 FS 전체 조건에서 일관된 품질 우위는 관측되지 않았다.** Astra는 양쪽 모두 제품 조건과 적격 완료 3/3, 설계 점수 100/100으로 같았고, FS 총 토큰 중앙값은 1,878,887로 일반 408,953의 **4.59배**였다. Sol은 일반 3/3·FS 2/3 적격 완료였으며, FS의 한 회차는 핵심 파일이 미완료라 0점이었다. Luna는 양쪽 모두 적격 완료 0/3이었다. FS에서 제품 조건을 만족한 1건도 근거 없는 자체 Q10 만점 선언 때문에 전체 적격 완료에는 포함되지 않았다.

## 현재 지식 버전에서의 결론과 한계

결론의 기준은 **FS 0.2.0 / 지식 문서 479개 / 학습 참조 69개 / 최근 갱신 2026-09-28T07:15:43.974Z**인 고정 스냅샷이다. [실제 지식 노출 감사](results/model-runs-2026-10-01T090255/knowledge-exposure.json)에서 A FS 9회는 학습 요약 노출 0건, B FS 9회는 모두 `get_work_context`의 지식 요약 노출이 확인됐다. 명시적 지식 검색 도구 호출이나 learned/source 원문 경로 직접 조회는 관측되지 않았다. 이는 완료된 도구 결과와 명령 텍스트 범위의 감사이며, 479개 문서를 모두 읽거나 요약을 실제 채택했다는 뜻은 아니다.

이 과제에서는 현재 FS 절차·지식 묶음이 추가 비용을 상쇄하는 일관된 품질 이득을 보여주지 못했다. A는 절차 비용, B는 전체 FS 사용의 관측이므로 이 결과로 지식만의 인과 효과를 분리할 수 없다. 지식 수가 늘었다는 사실만으로 품질 향상을 결론 내리지 않는다.

조건별 n=3, 단일 checkout, medium, 새 세션의 첫 구현만 측정했다. 통계적 우월성·다른 업무/추론 설정·누적 기록 재사용의 절감이나 손익분기점을 주장하지 않는다. 공개된 이진 20항목 점수는 만점이 많아 미세한 품질 차이를 가리기 어렵고, 필수 기능 판정이 별도로 필요했다. 독립 리뷰어는 작성 세션과 분리했지만 코드 형태로 조건을 추측할 수 있어 완전 블라인드는 아니다.

공통 격리 환경에서 네이티브 파일 작성/이미지 helper와 Git 전역 설정 조회가 제한됐다. 우회·정책 수정·문맥 재조회 비용도 실측에 포함돼 있으며, 이 환경의 FS 비용을 일반 개발 환경 전체로 일반화하지 않는다. `checkJs:false`는 엄격한 정적 타입 검증이 아니며, 브라우저는 Chromium·개발 서버이고 독립 JSX 수명 probe는 전체 React renderer가 아닌 결정적 hook 실행이다. 고정 결함 교정·실제 브라우저 검사·소스 리뷰를 함께 사용했으나 모든 결함 부재를 보장하지 않는다.

기존 미커밋 변경·v1 자료와 원점수를 보존했다. [최종 무결성 확인](results/model-runs-2026-10-01T090255/final-integrity.json)에 고정 파일·FS 스냅샷·결과 소스 해시 검증을 기록했다. 지식을 갱신한 다음 비교는 같은 조건의 새 스냅샷으로 분리해야 한다.

FS의 정책 명령 오기와 수정 비용도 포함했다.

첫 회차의 모델 완료 뒤 실행기 후처리가 중단됐다. 기존 모델 결과·토큰·동일 해시의 소스를 보존하고 외부 채점만 복구했다. [복구 기록](results/model-runs-2026-10-01T090255/01/post-model-recovery.json)을 남겼으며 모델 호출을 재실행하지 않았다. 이후 실행기 stdout/stderr는 파일에 직접 보존한다. FS의 Git 조회가 격리된 전역 설정 읽기에서 실패해 프로젝트를 미커밋 상태로 기록한 실행 제약도 보존했다.

26회차의 미완료 UI가 HTTP 500을 반환하자, 원래 서버 준비 검사가 HTTP 200만 허용하여 후처리가 중단됐다. [정상·HTTP 500 교정](results/model-runs-2026-10-01T090255/http-readiness-calibration/summary.json) 후 응답 가능한 오류 페이지에도 **원래 110개 assertion**을 적용했다. [복구 기록](results/model-runs-2026-10-01T090255/26/post-model-recovery.json)과 중단 당시 로그를 보존했으며 모델·사용량·제품 소스는 재실행하거나 바꾸지 않았다. 이후 수집은 [복구 실행기](resume-with-http-errors.py)를 통해 동일 고정 조건으로 완료했다. 최종 36회 재채점에도 이 준비 검사 보정을 동일하게 적용했다.

재개 명령의 상대 출력 경로 때문에 CLI의 `final.md` 별도 저장이 실패한 회차는 보존된 `events.jsonl` 마지막 완료 메시지를 그대로 추출했다. 각 `model/final-extraction.json`에 원로그 해시와 메시지 ID를 남겼으며 구현·사용량·채점은 바꾸지 않았다. 공통 격리 환경에서 네이티브 `apply_patch`와 이미지 읽기 helper가 실행되지 않는 제한도 관측됐다. 구현 모델은 허용된 셸 쓰기를 사용했으며, 이 환경의 우회·수정 비용을 결과에서 빼지 않는다.

## 재현

저장소 루트에서 실행한다. 기존 설치 의존성을 사용하며 새 패키지를 설치하지 않는다.

```sh
python3 test/evals/fs-comparison/v2/calibrate.py
node test/evals/fs-comparison/v2/preflight.mjs
python3 test/evals/fs-comparison/v2/prepare.py test/evals/fs-comparison/.work/my-v2-a --experiment A --dependencies
node test/evals/fs-comparison/v2/grade.mjs test/evals/fs-comparison/.work/my-v2-a test/evals/fs-comparison/.work/my-v2-a-score
```

`prepare.py`는 대상이 이미 있으면 중단한다. `--dependencies`는 macOS `cp -cR`로 설치된 fixture 의존성을 복사한다. B는 `--experiment B`, 참조 구현은 평가자 환경에서만 `--variant flat|layered`를 사용한다. 생성한 TASK의 문서 의무가 A/B에 맞는지 확인한다. 교정 중에는 임시 사본을 매번 새로 만들고 삭제한다. `frozen.json`이 있으면 재교정을 거부한다.

현재 preflight는 준비 미완료를 나타내는 종료 코드 2를 반환한다. grade는 사례 실패도 JSON에 기록하므로 프로세스 종료 코드만으로 통과를 판단하면 안 된다. 실행 가능한 서버가 있는 별도 검증 환경에서는 grade의 마지막 인자로 해당 서버 URL을 제공하면 브라우저 검사를 시도한다. 현재 교정 명령은 브라우저를 실행하지 않는다.

## 이전 세션의 차단 기록

[현재 대화 세션의 환경 점검](results/session-recheck/preflight.json)에서 `127.0.0.1` listen은 `EPERM`, Chromium은 macOS 프로세스 권한 오류로 실행하지 못했다. 이 세션에서는 권한 확장이 허용되지 않아 브라우저 교정과 본 모델 실험을 시작하지 않았다.

실제 비교 재요청 후 [환경을 다시 점검](results/recheck-2026-09-30/preflight.json)했고 같은 실패를 확인했다. Codex CLI 0.159.0으로 새 ephemeral·read-only Astra 세션의 최소 연결 검사도 시도했으나, [실행 로그](results/recheck-2026-09-30/connection-stderr.log)의 `failed to initialize in-process app-server client: Operation not permitted`로 모델 실행 전에 종료됐다. [연결 검사 기록](results/recheck-2026-09-30/connection-summary.json)은 완료 턴 0, 사용량 미수신이며 본 실험에 포함하지 않는다. 이를 모델 실패율이나 0토큰 결과로 계산하지 않는다. 현재 세션에서 서버·브라우저뿐 아니라 독립 모델 실행도 막혀 있다.

서버·Chromium을 실행할 수 있는 환경에서 정상/결함 브라우저 교정을 마쳐야 한다. 이어 독립 의미 리뷰 교정, 실제 구현 세션의 정답지·결과 읽기 차단 확인, A의 허용 FS 기능 분리, 새 세션 실행기·사용량 수집 연결, 전체 조건/순서/제한의 해시 고정이 필요하다. 경로를 숨기거나 별도 cwd를 쓰는 것만으로 격리를 주장하지 않는다. v1 실행기의 full-access 설정을 재사용하지 않는다.

| 본 실험 | 예정 실행 | 현재 토큰·품질 측정 |
| --- | --- | --- |
| A: 동등 산출물의 절차 비용 | 3모델 × 일반/FS × 3회 = 18회 | 미실행 |
| B: Clean Code·Architecture 품질 | 3모델 × 일반/FS × 3회 = 18회 | 미실행 |

준비 도구의 모델 호출은 0회다. 이는 모델 사용량 측정값 0토큰이라는 뜻이 아니다. v1 수치나 교정 통과율을 v2 토큰 절감·품질 향상 결과로 옮기지 않는다.

현재 결론은 **새로 정의한 A/B 질문에는 아직 실측 근거가 없어 우열을 판정할 수 없다**이다. 실제 비교에는 독립 Codex 세션·로컬 서버·Chromium을 실행할 수 있는 허용된 환경이 필요하다. 그 환경에서도 위의 리뷰·격리·실행기 준비를 끝낸 뒤 측정해야 한다. 이후 결론은 실행 당시 고정한 FS 버전·규칙·지식 스냅샷·모델·과제에 한정한다. 프론트엔드 지식 추가 후에는 같은 비교 조건으로 새 스냅샷을 평가하고 이전 결과와 분리해 기록한다. 지식 추가가 결과를 바꿀 수 있으나 개선 방향을 미리 보장하지 않는다.

이어받는 세션은 이 문서와 `../v2-protocol.md`, `../v2-oracle.md`를 읽고 위의 남은 준비를 완료한다. 기존 미커밋 변경과 v1 원자료를 보존한다. 사용자 요청은 준비 보고로 끝내지 않고 실제 A/B 비교 및 README 결론까지 진행하는 것이다. 정상 참조·결함·비공개 정답지는 구현 모델에 전달하지 않으며, 새 세션·초기 소스·기록 초기화와 모델별 사용량 수집을 유지한다. 환경 확인이 통과해도 브라우저 교정·독립 리뷰·격리·실행기는 아직 미완료라는 상태에서 시작한다.
