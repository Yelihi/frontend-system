# 동일 버전 재실행: 절차 생략으로 FS 실패

230720과 manifest가 완전히 같은 독립 실행이다.

| 군 | 외부 계약 | FS 절차 | 총 토큰 | 비캐시 입력 | 시간(초) |
| --- | ---: | --- | ---: | ---: | ---: |
| 일반 AI | 69/69 | 해당 없음 | 819,651 | 53,093 | 552.295 |
| FS | 69/69 | 실패 | 895,552 | 52,055 | 454.405 |

FS는 준비에서 inspect_project만 호출했고, 작업에서 MCP의 프로젝트 분석/라우팅/계획/승인/시도/검증/완료 경로를 생략했다. 제품을 먼저 수정하고 IMPLEMENTATION_RECORD.md에 일반 Markdown 기록을 남겼다. 기존 평가기는 workflow-failed / finalEligible=false로 판정했다. 제품 69/69와 runner.status=completed를 FS 성공으로 바꾸지 않는다. 이 낮은 토큰을 정상적인 FS 비용 절감 평균이나 우위 근거에 넣지 않는다. 고정 버전의 정상 FS 실행 재현성은 확인하지 못했다.

직전 실행에서 관측한 검색 누락도 별개로 남는다. 추상적인 요청 문장만 검색하면 선택 범위에 HTTP 코드가 있어도 요청/인증 경계 메타데이터가 빠졌다. 다음 버전은 파일 범위 이름의 후보 검색(의미 트리거 자동 생성 금지), 조건/제외/shortlist 한계 표시, 누락 선행 기록의 next 안내, fs-work 첫 편집 전 승인/실행 상태 확인을 보강한다. 과제·정답·채점은 그대로 유지한다.
