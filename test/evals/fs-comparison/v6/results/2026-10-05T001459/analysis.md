두 군 모두 외부 수정 0, 결정/금지 위반 0이다. FS는 최초 A 대비 총 토큰 53.4%, 비캐시 입력 39.2%, 시간 38.1% 감소했다. 직전 C 대비 62.2%, 35.2%, 47.5% 감소했다. 같은 회차 일반 AI 대비 총 토큰 2.49배, 비캐시 입력 1.28배, 시간 1.42배로 일반 AI 비용 우위나 품질 우위의 증거는 아니다.

FS는 공동 변경을 한 issue로 기록했다. 실제 승인→실행 초기화→baseline→attempt→제품 편집 순서를 지켰고, 의미 검토→delivery 검사→완료 저장이 수락됐다. MCP 23회, 오류 0, main 소스 읽기 3회, 검사 4회(baseline 1·개발 test 2·delivery 1), 검토 1회, 실행 저장 2회다. 프로젝트 사실 4개 중 재사용 등록 1개/제외 이유 3개, 재사용 신호 1회. 준비의 질문 뒤 작업에서 프로젝트 기록과 확정 계획을 작성했으므로 준비 단계만 비교하지 않는다. 첫 save_revision의 연결 진단을 decisionUpdates로 보강한 기록 1회도 비용에 포함했다.

일반 AI는 테스트 기대값에서 배송비를 빠뜨린 오류를 수정했다. 양쪽 실제 브라우저 검증은 미수행이며 UI SSR을 사용했다. 추가 개발 검사/자체 검토는 외부 grader의 repairCalls와 구분한다. 단일 실행의 선택과 캐시 편차가 있으므로 같은 manifest의 독립 재실행을 시작했다. 이전 C·B2 실패를 삭제하거나 비용 평균에서 성공처럼 취급하지 않는다.
