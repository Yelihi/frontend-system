양쪽 8개 질문/답 반영, 금지 위반 0. FS 저장·라우팅·승인·완료 경로 관측. FS 재사용 사실 1개, 두 문맥 조회에서 신호 합계 2회, 답변+경로 부분 수정 1/1, full revision 읽기 0회. 32개 제품 파일 중 25개는 바이트가 같다. 다른 7개의 차이는 점수 우위로 환산하지 않는다. UI는 모의 이벤트/SSR/빌드이고 실제 브라우저는 미검증이다.

FS는 38개 MCP 호출, shell 25개였다. 소스 묶음 18개를 균등 1,333자로 나눠 checkout/system의 나머지를 각각 한 번 더 읽었다. 문서 저장 expectedHash에 sourceHash를 잘못 넣어 프로젝트 저장을 다시 했으며, 다른 plan 범위의 baselineCheckId를 실행에 연결해 거부된 뒤 해당 plan의 기준 검사를 다시 했다. 검사는 baseline 3회(서로 다른 범위 포함), 개발 3회, delivery 1회다. 개발 검사는 모두 통과했으며 테스트 범위를 추가했다. 일반 AI는 자체 테스트 fixture의 잔액 오류 1회를 수정했다. FS의 브라우저 실패는 환경 제한이고 입력 오류 2건과 별개다.

후속 개입은 (1) 총 24,000자 상한 내 읽기 공간 재분배, (2) documentHash/commit 매핑 명시, (3) 계획 단계의 불필요한 baseline 실행 방지와 같은 planId 연결 안내다. 승인·현재 근거·외부 채점·시도 제한은 보존한다. 성능 향상은 후속 실측 전에는 미확인이다.
