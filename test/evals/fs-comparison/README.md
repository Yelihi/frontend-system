# FS 사용 여부별 통제 실험

같은 모델 안에서 일반 Codex와 FS를 비교한다. 과제는 저장소의 Next.js 주문 예제에 [동일한 요구사항](prompt.md)을 구현하는 것이다. 한 과제의 소규모 반복 실험이며 일반적인 프론트엔드 작업 전체의 우열을 입증하지 않는다.

## 실행 전에 고정하는 조건

- 모델: GPT-6 Astra / Sol / Luna, 모두 `medium`. 조건마다 3회, 총 18회.
- 회차별로 모델 순서를 회전하고 일반/FS 순서를 교대로 바꾼다. 실행은 순차 수행해 로컬 CPU·브라우저 경합을 줄인다.
- 원본 fixture는 같은 Git 커밋에서 추출한다. 매 실행에 새 저장소·main 초기 커밋·독립 node_modules 사본을 만든다. `.next`, 프로젝트 메모, 이전 변경·세션은 가져오지 않는다.
- 임시 작업은 Git에서 제외한 `.work/`에 만들고 정상 종료 시 삭제한다. FS 스냅샷은 실행 전후에 해시를 확인한다. 무결성이 깨지면 원자료를 보존하고 다음 실행을 중단한다.
- 매번 새로운 `codex exec --ephemeral --ignore-user-config --ignore-rules` 프로세스를 사용한다. 개인 스킬, 설치 플러그인, 메모리, hooks, apps, 하위 에이전트, 웹 검색을 비활성화한다. 사용자/상위 프로젝트 AGENTS 자동 주입도 끄며 프로젝트 안의 같은 문서는 양쪽이 직접 읽을 수 있다.
- macOS의 `workspace-write`는 사전 점검에서 Chromium 실행을 막았다. 해당 파일럿은 본 비교에서 제외하고, 양쪽 모두 현재 호스트와 같은 `danger-full-access`로 실행한다. 프로젝트·대화 초기화는 새 프로세스와 별도 파일 사본으로 수행하며 OS 수준의 읽기 차단을 의미하지 않는다. 외부 프로젝트·개인 기록 접근은 공통 지침으로 금지한다.
- 두 조건의 사용자 프롬프트는 바이트 단위로 같다. FS 조건만 현재 저장소에서 고정한 스킬·참조·규칙·MCP 번들을 제공하고 `fs-plan → fs-work` 절차를 사용하도록 활성화 지침을 넣는다. 이 추가 지침과 MCP/문서 비용도 FS 토큰에 포함한다.
- 외부 채점 코드는 모델 실행이 끝난 뒤에만 적용한다. 채점 결과를 다시 모델에 전달해 수정하지 않는다. 모델이 자체 추가한 테스트의 개수로 점수를 높이지 않는다.
- 실행당 모델 작업 제한은 900초. 실패·시간 초과·FS 미사용도 기록하며 성공 사례만 골라내지 않는다. 인프라 실패는 제품 결함과 구분한다.
- CLI 버전, 요청 모델, 추론 설정, Node/OS, 소스·프롬프트·FS 파일 해시, 세션 ID, 실행 순서와 시간을 보존한다. 요청 모델과 서버가 별도로 확인해 준 모델 정보는 구분한다.

## 지표

| 지표 | 계산·의미 |
| --- | --- |
| 토큰 | `turn.completed.usage`의 input, cached input, output, reasoning output 원값. input은 cached input을 포함하므로 중복 합산하지 않음 |
| 비캐시 입력 | input − cached input. 캐시 상태를 강제 초기화할 수 없어 별도 보고 |
| 총 토큰 | input + output. reasoning은 제공된 별도 필드로 보고하며 총량에 다시 더하지 않음 |
| 기능·계약 | 고정한 도메인/API/브라우저 요구사항별 통과 수 / 실제 예정 검사 수. 실행 불가·시간 초과는 통과로 처리하지 않음 |
| 기본 검사 | 원본 lint·typecheck·경계·unit·build·E2E의 성공/실패/미실행 |
| 접근성·반응형 | 레이블·키보드 주문·오류/성공 알림·360px overflow 검사. WCAG 전체 준수 점수가 아님 |
| 브라우저 오류 | 고정 시나리오의 pageerror 건수. 모든 사용자 경로의 무오류 보장이 아님 |
| JS 전송량 대용치 | 성공한 production build의 `.next/static/**/*.js` 각각을 gzip한 크기의 합. 실제 초기 페이지 전송량이나 Lighthouse 점수가 아님 |
| 변경량 | 제품 파일·추가 테스트와 FS 기록을 나눠 변경 파일/추가·삭제 줄 수 기록. 줄 수 자체를 품질 점수로 취급하지 않음 |
| 소요 시간 | 모델 프로세스 시작부터 종료까지 wall time. 서버 혼잡과 모델 자체 검사 시간이 포함됨 |
| FS 수행 여부 | MCP 호출 수·사용 도구·계획/실행/검증 기록. FS 활성화만으로 전체 절차를 수행했다고 간주하지 않음 |

각 실행값과 모델/조건별 중앙값·최솟값·최댓값을 함께 제시한다. 3회 결과에 유의성이나 일반적인 토큰 절감률을 주장하지 않는다. 캐시는 대화 문맥과 다르며 서버 캐시 초기화는 통제할 수 없다. 제품 코드의 초기 해시는 모든 실행에서 같아야 한다.

실행 순서는 사전에 정한 회전 순서이며 무작위 배정은 아니다. 샘플링 시드와 서버 부하는 통제하지 않는다. 파일·지침·버전을 재현해도 결과물이나 토큰 수가 정확히 같아진다는 뜻은 아니다.

프로젝트 검사 명령은 기존 설정으로 실행하며, 모델이 추가한 E2E도 발견될 수 있다. 모델이 추가한 잘못된 테스트 때문에 명령이 실패한 경우도 프로젝트 검사 실패로 기록한다. 조건마다 같은 외부 33개 사례의 결과와 이 값을 분리해 해석한다. 토큰 표는 평가 대상 세션의 사용량이며, 실험 설계·채점 담당 세션과 사전 점검 호출 비용은 포함하지 않는다.

기존 검사 파일의 해시 변경은 변경 여부를 뜻하며 그 자체로 검사 약화나 제품 결함을 입증하지 않는다. 사례 추가, 의미를 유지한 선택자 수정, 보장의 삭제를 diff로 구분한다. 원본 테스트를 복원했을 때의 선택자 충돌도 실제 주문 동작 실패와 구분한다. 누적 입력 토큰은 여러 모델 요청의 합이며 단일 컨텍스트 길이가 아니다.

## 재현

```bash
npm ci
npm run build
npm --prefix test/fixtures/frontend ci
npm --prefix test/fixtures/frontend exec -- playwright install chromium
python3 test/evals/fs-comparison/run.py
python3 test/evals/fs-comparison/report.py test/evals/fs-comparison/results/<실행-시각>
```

모델 호출 없이 사용량 집계기를 확인하려면 `python3 test/evals/fs-comparison/test_run.py`를 실행한다. 모델 실험은 일반 CI나 `npm test`에 자동 연결하지 않는다.

기존 Codex CLI와 ChatGPT 로그인을 사용하며 별도 유료 API를 추가하지 않는다. 실제 모델 실행은 계정 사용량을 소비한다. `--models`, `--repeats`, `--timeout`으로 후속 실험을 별도 결과 디렉터리에 실행할 수 있다. 원문 JSONL·최종 답변·diff·채점 로그·실행별 JSON을 보관한다. README 결과 표는 완료한 실행에서 계산하며 예상 수치를 쓰지 않는다.

## 2026-09-30 실행 중 예외

본 비교 이전의 `2026-09-30T020042`는 초기 자료에 남은 FS 기록을 발견한 사전 점검이며 모델을 실행하지 않았다. `2026-09-30T020124`는 브라우저 sandbox 문제를 확인한 파일럿으로 집계에서 제외했다. 파일럿 JSONL은 압축 처리 실수로 유실됐으며 해당 결과에 명시했다. 본 비교의 JSONL은 별도로 보존한다. 파일럿에서 발견한 Next.js 전역 alert 선택자 오탐은 본 비교의 첫 외부 채점 전에 수정했고, manifest에 변경 전후 해시를 기록했다.

본 비교 중 OS 임시 경로의 FS 문서 8개 유실을 관측했다. 삭제 원인은 확인하지 못했으며 디렉터리 변경 시각은 Astra 세 번째 FS 실행 도중이었다. 해당 일반/FS 쌍을 `excluded/`에 보존하고 두 조건을 새로 실행했다. 재측정부터 저장소 내부 작업 폴더와 매 실행 전후 해시 검사를 사용한다. 최초 실행기·환경과 변경 이유는 [사건 기록](results/2026-09-30T020539/runtime-integrity-incident.json), `runner-original.py.gz`, `retry-manifest.json`에 남겼다. FS의 정책 작성 오류나 미완료 상태는 이 인프라 제외와 구분하며, 그 이유로 재실행하지 않았다.

마지막 Astra FS 결과는 `Total` output의 역할을 group으로 지정해 고정 채점기의 status 선택자에서 두 사례가 실패했다. 프롬프트보다 강한 역할 가정이므로 기능 결함 두 건으로 해석하지 않는다. 고정 점수 31/33은 유지하고, 동일한 제품 코드 해시에서 해당 역할 제한만 제거한 사후 진단 33/33을 별도 보존했다. 진단의 코드 차이·준비 과정·로그는 해당 실행의 `selector-diagnostic/`에 있다. 모델 재호출이나 본 비교 점수 수정은 하지 않았다.

세션 격리와 JSON 사용량 필드는 [공식 비대화형 실행 문서](https://developers.openai.com/codex/noninteractive), 설정은 [공식 설정 참조](https://developers.openai.com/codex/config-reference)를 기준으로 로컬 CLI 도움말과 함께 확인했다.
